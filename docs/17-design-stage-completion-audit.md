## 4. 七类场景走查

### 4.1 正常主路径

Visitor 提交问卷并看到真实推荐；注册事务创建待验证账户并一次性认领 Intake，验证与登录后保存接受／Override 决定，再创建或复用 Ready Run。正式开始固定 Task Version、Decision Profile 和来源决定。必需反思提交时关闭 Run、冻结输入引用、产生确定性 NEXT 并持久化快照 job；快照与报告异步生成。两项单专业报告可用后生成比较报告；第三项扩展同一个逻辑比较报告。

设计证据：`06` 生命周期、`08` 规则、`09` 任务、`10` 报告、`11` 事务、`12` 端点、`14` 状态。

### 4.2 重复提交与并发

注册认领、推荐决定、创建运行、执行、Reflection、反馈、导出和删除使用 Idempotency-Key；步骤草稿使用 expectedRevision；数据库约束保证同一学生最多一个活动运行。旧标签页返回冲突并显示服务端版本，不静默覆盖。

设计证据：`11` 唯一约束和事务、`12` §5、`14` 冲突状态、`15` 并发测试。

### 4.3 故障与恢复

Intake、任务草稿、领域状态及后台 job 以 MySQL 为事实来源。暂停切换保留同一 Run 的进度和版本；异常恢复将未完成旧运行置 REPLACED，再创建有审计的新 Ready。作业在重启后重新领取，租约版本拒绝旧 worker 迟到发布。快照失败可追加构建版本；模型失败可基于 READY 证据降级。本地草稿分账户隔离，主动退出／换账号／删除时清理，自然过期仅原账户可恢复。

设计证据：`03`、`10`、`11`、`14`、`15`。

### 4.4 越权与身份串用

Intake Cookie、Student Session 和 Operator Token 分属三条安全边界。所有私有资源读取验证主体和所有权；学生管理路径交叉访问、操作者直接充当学生、猜测 publicId 均失败。敏感内部查看和导出需要独立权限和审计。

设计证据：`03` §6、`11` 身份表、`12` 安全链、`13` 威胁矩阵、`15` 负向测试。

### 4.5 任务与规则升级

新规则只产生新 Recommendation；新任务版本只分配给尚未开始的运行；已开始运行固定 Task Version；旧报告固定原 Decision Profile、Evidence Snapshot、模板、提示词和模型信息。退役内容不改写历史。

设计证据：`06`、`08` §10、`09` 版本、`10` 版本、`11` 外键与不可变边界。

### 4.6 报告生成失败

Experience Run 的 Closed 与 Report 的生成状态分开。结构错误或越界声明最多修复一次，之后发布确定性降级报告；失败报告版本不能成为 current version。学生无需重做任务，页面展示生成、重试或有限个性化状态。

设计证据：`06` §11、`10` 验证流水线、`11` Report Version、`12` Report API、`14` 失败状态。

### 4.7 账户删除

删除确认立即进入 DELETION_PENDING、撤销全部会话并阻止正常资源访问；此前预置的专用回执 Cookie 仅可查询状态和时间。删除 job 按阶段清理个人内容、报告、事件、作业与幂等引用，目标30天内完成；发布事务的账户锁与状态检查阻止迟到数据回写。完成后只保留不可反查原账户的回执，最多90天且不晚于确认后120天；公开部署前仍需法律复核。

设计证据：`11` §12–13、`12` 删除 API、`13` 隐私界面与留存、`15` 删除测试。

## 5. 系统责任唯一性

| 组件 | 唯一主要责任 | 明确不负责 |
| --- | --- | --- |
| `student-web` | 公共、Intake、学生身份、任务、报告界面和本地草稿 | 管理权限、保存服务端秘密、决定规则结果 |
| `admin-web` | 内部查询、发布、恢复、导出和审计界面 | 学生体验导航、直接改写答案或报告 |
| Spring Boot 单体 | 身份、规则、状态机、所有权、证据、报告验证和适配器 | 把 Redis/前端事件当唯一事实 |
| MySQL | 账户、版本、进度、证据、报告、事件和审计的持久事实 | 执行任意用户代码、保存明文令牌 |
| Redis | 会话/令牌缓存、短期缓存和限流辅助 | 唯一保存进度、报告或推荐 |
| 浏览器执行 Worker | 执行任务白名单内的轻量代码和数据 | 任意网络、本地文件、服务端秘密、最终授权判断 |
| AI 服务 | 解释、分层提示、有限反思追问和结构化草稿 | 改写规则、判定适配、成为未经验证的事实来源 |
| 版本化内容 | 固定问卷、规则、任务、数据、提示和 schema | 按用户临时生成未经审核的完整任务 |

本轮按此分工修订了评分、作业、事件与删除责任；其真实实现仍须通过 P0–P8 测试，不能把责任表当运行证明。
