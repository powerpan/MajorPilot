## 1. 已落地的范围

- 精确固定 RuoYi 后端与 Vue 3 TypeScript 管理端来源，保留许可证及导入、修改记录。
- Maven Wrapper、固定 Node/npm、依赖 lockfile、独立 `ruoyi-majorpilot` 模块和双前端。
- 项目专用 MySQL 8.4.11、Redis 7.2.16、Mailpit 1.31.2；没有改动本机其他项目服务。
- 环境文件安全加载、随机本地凭证、前端环境白名单、带 PID 身份检查的启动／停止入口。
- Flyway 上游基线与 `mp_p0_*` 合成数据迁移、最小学生／管理安全链、签名 CSRF、Cookie 路径、删除回执探针。
- MySQL 持久化作业原型：事务领取、租约、代次栅栏、心跳方法、有限重试及删除状态检查。
- 独立 hostname 与 opaque iframe 内的可信 Worker 固定计算器；不执行用户代码。
- Fake／Replay／百炼 Java 适配器与开发诊断脚本、OpenAPI 3.1、JSON Schema、安全错误与请求日志骨架。

`mp_p0_actor` 不是正式 Student Account；合成认领、测试密码、同步删除和合成邮件，不构成 P1/P7 的注册、验证、密码重置或个人数据删除实现。后续应追加迁移与正式实现，不修改已经执行的 V1/V2 来冒充业务完成。

## 3. 已发现并修复的问题

1. 官方 MySQL 在受限沙箱中初始化 SIGSEGV，堆栈位于 `Aligned_atomic`；`hw.cachelinesize` 查询被拒绝。通过正式权限审批在沙箱外执行同一项目专用初始化后成功，没有换数据库版本，也没有修改沙箱策略。诊断技能促使先复现、核对权限原因再重试；这不是对 MySQL 源码的修复。
2. 上游日志默认 `/home/ruoyi/logs` 不适合本机：先以外部 Logback 配置验证原始 jar，再将项目日志改成受控相对目录。
3. Spring 配置导入顺序覆盖了 P0 数据源：改为所有有效配置都必须使用环境占位符，并在建立连接前校验本项目库、用户和端口；第一次错误连接未认证成功、未写数据。
4. Flyway 的能力探测与 Druid 对 SQL 错误的连接处理冲突：迁移使用独立数据源，没有为应用用户增加 `performance_schema` 广泛权限。
5. 上游 MyBatis 自建工厂可能早于 Flyway 查询基础表：明确依赖迁移初始化器。
6. 初始生成的管理员密码超过若依 20 字符限制：改为 20 位 base64url 随机值（120 位随机性），仅轮换本轮生成的 P0 管理口令，并加入长度校验。没有改模型密钥。
7. MySQL CLI 的 `--defaults-extra-file` 会混入用户全局配置：改成项目 `--defaults-file`、禁用 login-path、强制项目 Unix socket，并增加回归测试。
8. 下载中断可能留下被误认为完整的缓存：采用唯一 partial、校验后原子改名，坏缓存只隔离保留，不递归删除用户文件。
9. 沙箱内 `ps` 不可用会误判已启动进程：启动／停止前先检查进程可观察性，失败即停止操作；PID、启动时间、完整命令一致才可结束进程。
10. 浏览器 Cookie 测试改用 `allHeaders()` 并加入主站 `Path=/` 合成哨兵作正向对照，避免只因 Path 不匹配或 API 隐藏 Cookie 导致假通过。
11. 上游 Vue 声明覆盖了真实类型：改为正确的类型扩展后，暴露出 248 条严格检查诊断；完成组件／表单引用、可空数据、API 模型等有界修复后清零，保留 `strict: true`，并使生产构建强制先做类型检查。没有用全局 `proxy:any` 或批量忽略掩盖问题。
12. 第一次干净源码快照没有包含管理端 lockfile，因为上游 `.gitignore` 忽略了它：已删除该忽略规则，并核对五个 npm lockfile 均可被 Git 纳入。失败目录与日志保留，无服务启动；后续复现使用另一个全新目录，不复用失败安装历史。
13. 健康检查新增依赖状态后，OpenAPI 仍只有旧字段：补齐六个必填字段及 HTTP 503 的状态响应，增加成功、故障和缺字段回归，并校验实际 HTTP 200 响应，避免只验证路由清单就声称响应合同一致。
14. 最终统一 E2E 曾在邮件阶段返回 500，而四组浏览器检查均通过。原生 SMTP 完整交易和两个独立 Java 探针均成功；运行中 JVM 的请求稳定 5 秒失败，线程栈停在 `SMTPTransport.close` 等待 QUIT 响应。只重启同一后端 JAR、保持 Mailpit／数据库／配置不变后，完整 API 与两类邮件测试恢复。构建覆盖了正在运行的 `target` JAR，是目前有强对照证据支持的原因推断，但没有捕获到更底层资源异常，不将推断写成已证实的精确异常链。Spring Boot 通过外层 JAR 文件偏移加载嵌套资源，机制参考[官方 3.5 说明](https://docs.spring.io/spring-boot/3.5/specification/executable-jar/jarfile-class.html)。现由 `runtime-artifact.mjs` 将完成的 JAR 复制成独立的 SHA 内容寻址只读文件，正常启动与作业重启探针统一使用它；4 项新单元测试及同 JVM 热构建＋API／邮件回归通过，没有延长超时或忽略失败。原始运行包保留在忽略的 `data/runtime/`，不自动清理。

## 4. 明确保留的风险／后续门禁

- 百炼严格 JSON Schema 400 的具体原因尚未进一步诊断；JSON Object + 服务端白名单校验已按原设计可行。没有放宽正式报告真实性边界。
- 真实账号容量、RPM/TPM／优惠额度、自然 429 和真实超时没有被强行制造或验证；本地 HTTP stub 验证的是处理逻辑。2026-09-20 用户确认 P0 采用现有小量真实调用与本地故障注入证据，真实容量压测移为上线前门禁；执行前需明确负载、配额和费用上限。本轮不再增加模型调用。
- Pyodide 普通启动成功，但严格 `connect-src 'none'` 架构未通过；用户可编辑 Python／表达式保持关闭。固定计算器的结果会随有效输入变化，不是固定演示答案。
- ECharts 5.6.0 的 moderate 安全通告尚未通过跨主版本升级处理；不开放用户控制的图表配置/HTML。Axios、js-cookie 同主版本安全补丁的来源和回归见管理端记录。后续使用图表前需关闭此风险。
- 干净目录复现与独立全新机器不是一回事；同机重建成功也不能声称跨平台、独立机器已验收。
- 无真实用户验收、备份恢复演练、公网 TLS／域名／SMTP 生产接入；这些不得写成已完成。
