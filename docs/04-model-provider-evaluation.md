# MajorPilot 模型服务评估与接入基线

> 状态：首个接入路线与后端边界已确认 v0.3  
> 更新日期：2026-09-20  
> 信息时点：2026-09-20，模型、价格和区域能力后续可能变化  
> 关联文档：[技术约束与架构边界](./03-mvp-technical-constraints.md) · [RuoYi 基线选型](./05-ruoyi-baseline-selection.md)

## 1. 结论

MVP 已确认优先接入 **阿里云百炼 Model Studio** 作为首个开发服务，但暂不把具体 Qwen 模型永久写死。DeepSeek 进入离线对照评测；只有在百炼和 DeepSeek 都不能满足要求时，再加入 OpenAI 对照。MVP 运行时不同时路由多个供应商。

推荐顺序：

1. 先完成供应商无关的模型适配接口；
2. 使用现有百炼权限接通首个可运行版本；
3. 用 MajorPilot 自己的任务样例比较 Qwen、DeepSeek 和一个 OpenAI 成本型模型；
4. 根据结构化输出可靠性、证据约束、中文表达、延迟和成本确定正式模型；
5. MVP 运行时只启用一个主供应商，避免过早增加路由、降级和账单复杂度。

选择百炼作为首个接入不是认定它一定质量最高，而是因为已经具备访问条件、中文场景适配自然、模型选择和区域较丰富，而且官方资料明确提供结构化输出和模型调用的数据保护说明。最终模型仍需以本项目的评测结果为准。

真实 API Key 存放在本地环境文件中，不使用 Apple 钥匙串，不写入仓库，也不下发到 Vue 前端。密钥只由 Spring Boot 后端读取。

## 2. MajorPilot 的真实模型工作负载

模型评估必须围绕以下任务，而不是使用通用聊天印象：

### 分层提示

- 理解当前任务步骤和用户已完成内容；
- 只提供当前层级的帮助；
- 不提前泄露核心答案；
- 在中英文术语之间保持准确对应；
- 延迟足够低，不打断任务节奏。

### 反思追问

- 根据用户真实操作提出一到两个有针对性的问题；
- 区分知识不足、工具困难、任务兴趣和任务设计问题；
- 不推断人格、智力或心理特征；
- 避免诱导用户迎合系统结论。

### 体验报告

- 严格区分行为事实、用户自述和系统解释；
- 只引用实际存在的证据字段；
- 分开描述体验偏好、当前准备度和本次任务表现；
- 输出符合固定结构的数据；
- 不生成适配度总分、录取概率或确定性人生建议。

### 首个专业推荐解释

- 基础推荐由规则系统决定；
- 模型只能解释规则结果，不能擅自改写推荐；
- 解释必须对应用户明确提交的信息；
- 用户改选时保持中立。

## 3. 候选服务比较

### 3.1 阿里云百炼 Model Studio

适合作为第一个开发接入：

- 用户已经具备平台使用条件；
- 官方提供 Qwen Flash、Plus 等不同成本与能力档位；
- 官方结构化输出文档支持 `json_object`，部分模型和区域还支持严格 `json_schema`；
- 官方说明 API 数据不会被用于模型训练；
- 支持按区域建立端点和密钥，便于以后结合数据位置要求选择区域；
- 同一供应商内可以先用较强模型建立质量基线，再评估低成本模型。

需要注意：

- 区域之间的端点、密钥、模型、功能和价格不同；
- 官方结构化输出页面当前注明新加坡区域尚不支持 `json_schema`，实际账号区域和目标模型必须单独验证；
- 官方隐私说明同时指出平台会存储模型或应用调用产生的数据，仍需核对具体区域条款、保存期限和可配置项；
- “不用于训练”不等于“不保存”，产品隐私说明不能混淆两者。

建议先评测一个 Plus 级模型作为质量基线，再评测一个 Flash 级模型是否能够承担高频提示。当前官方价格页列出了 `qwen3.7-plus`、`qwen3.8-flash` 等候选，但最终模型名称应在接入时从账号所在区域确认。

官方资料：[模型与价格](https://www.alibabacloud.com/help/en/model-studio/model-pricing) · [结构化输出](https://docs.modelstudio.console.alibabacloud.com/en/model-studio/qwen-structured-output) · [安全与隐私](https://docs.modelstudio.console.alibabacloud.com/en/model-studio/privacy-notice)

### 3.2 DeepSeek API

适合作为高性价比对照候选：

- 用户已经具备使用条件；
- 官方接口兼容常见 API 格式；
- Chat Completions 支持 JSON Output；
- Responses API 文档提供 `json_schema` 结构化输出；
- 当前官方模型页列出的 Flash 和 Pro 均支持 JSON 输出和工具调用。

需要注意：

- JSON Output 仍需要在提示中明确要求 JSON，并处理达到长度限制或输出不完整的情况；
- 在向其发送真实用户反思、教育背景和过程数据前，必须进一步确认 API 场景的数据保存、训练使用、地域和删除条款；
- 当前公开隐私材料不足以让我把它在敏感用户数据上的处理确定为优于百炼或 OpenAI；
- 因此，DeepSeek 可以先用合成数据参与本地质量和成本评测，不应仅凭价格直接成为用户数据的默认接收方。

官方资料：[模型与价格](https://api-docs.deepseek.com/quick_start/pricing) · [Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/) · [Responses API](https://api-docs.deepseek.com/api/create-response/) · [隐私政策](https://platform.deepseek.com/downloads/DeepSeek%20Privacy%20Policy.pdf)

### 3.3 OpenAI API

适合作为质量和数据控制对照候选：

- 当前模型系列提供成本型、均衡型和旗舰型档位；
- 官方模型页面列出的当前模型支持结构化输出；
- 官方说明 API 数据默认不用于训练，除非客户主动选择共享；
- 默认滥用监控日志可能保存最多 30 天，符合条件的客户可申请更严格的数据保留控制；
- 对结构化报告、证据约束和多语言指令遵循具有评测价值。

需要注意：

- 用户目前没有说明已经具备 OpenAI API 条件；
- 增加新供应商会带来账户、付费和合规审查成本；
- 不建议在没有对照评测收益的情况下，为 MVP 增加第三个生产依赖；
- 如果参与评测，可优先选择官方当前成本型或均衡型模型，而不是直接使用最高价旗舰模型。

官方资料：[模型目录](https://developers.openai.com/api/docs/models) · [模型比较](https://developers.openai.com/api/docs/models/compare) · [API 数据控制](https://developers.openai.com/api/docs/guides/your-data)

## 4. 适配层接口要求

模型适配层位于 RuoYi Spring Boot 单体的 MajorPilot 业务模块中，由学生端业务 API 调用。学生端和管理端前端都不得直接调用模型供应商。后端需要定义内部模型接口，至少包含：

- `generateHint`
- `generateReflectionQuestion`
- `generateExperienceReport`
- `explainInitialRecommendation`

每个接口使用项目自己的请求和响应对象，不向业务层暴露供应商 SDK 类型。统一处理：

- 供应商和模型标识；
- 提示词版本；
- 超时与有限重试；
- 结构化输出解析；
- JSON Schema 或等价校验；
- 输出字段白名单；
- 输入和输出长度限制；
- 错误分类；
- 调用量、耗时和估算成本；
- 测试环境模拟响应；
- 发送前的数据最小化和必要脱敏。

如果目标模型或区域不支持严格 `json_schema`，可以暂时使用 `json_object`，随后在服务端执行 Schema 校验，并允许一次有边界的修复重试。不能把未经验证的模型 JSON 直接写入正式报告或业务字段。

模型适配器通过服务端环境变量读取供应商、端点、模型和密钥配置。业务代码不得读取固定密钥字符串，也不得把密钥写入任一前端环境变量、配置接口、日志或异常响应。模型调用记录写入 MajorPilot 的 `mp_` 业务表或受控日志，不写入 RuoYi 管理用户表，也不得依赖 Redis 作为唯一记录。

## 5. 对照评测方案

### 5.1 评测集

在接入生产用户前建立一套固定、版本化的合成评测集，建议至少覆盖：

- 三个专业各自的正常任务进度；
- 用户完全不会、部分完成和表现较好的情形；
- 频繁求助、拒绝回答和中途返回的情形；
- 中英文混合输入；
- 与任务无关或试图索取直接答案的输入；
- 相互矛盾的自述与行为记录；
- 缺少关键证据的报告生成请求；
- 可能诱发专业适配分数、人格判断或录取预测的输入。

### 5.2 评价维度

每个候选模型使用相同输入和输出约束，比较：

- 结构化输出首次解析成功率；
- 修复一次后的解析成功率；
- 是否只引用允许的证据字段；
- 是否泄露核心答案；
- 是否过度推断；
- 中文表达是否自然、清楚和克制；
- 同一输入多次运行的一致性；
- 首字和完整响应延迟；
- 单次任务与单份报告的估算成本；
- 错误率、限流表现和恢复难度。

### 5.3 决策门槛

正式模型至少需要满足：

- 经过服务端校验和一次有限修复后，评测集全部得到合法结构；
- 不引用不存在的行为证据；
- 不输出被产品规则禁止的适配分数或录取概率；
- 分层提示不会在低帮助级别直接给出答案；
- 能够区分兴趣、准备度和任务表现；
- 延迟和成本在预期用户规模下可接受。

如果没有候选模型同时满足上述要求，应调整提示、输出结构或产品交互，不应通过放宽报告真实性要求来迁就模型。

## 6. 已确认的实施顺序

1. 先在 Spring Boot 中实现供应商无关接口和模拟适配器；
2. 接入百炼并完成四类工作负载的端到端调用；
3. 使用合成数据建立固定评测集；
4. 用 DeepSeek 跑同一评测集；
5. 如果两者在关键指标上都不稳定，再加入 OpenAI 成本型或均衡型模型作为对照；
6. 记录测试时的具体区域、模型快照、价格和数据条款；
7. 确定一个 MVP 主供应商和模型组合；
8. 真实用户数据接入前再次复核隐私、保存和删除条款。

当前不建议实现生产时的自动多模型路由。评测可以比较多个供应商，产品运行时保持一个主路径。
