# 五账号测试版

2026-10-14，用户确认按部署方案推进，并将第一轮范围收紧为五个预置测试账号。不开放注册，不要求邮箱验证，不接真实邮件。每个账号可生成三次单专业报告、两次比较报告。供应商 API key 可以放到服务器私有环境文件中，不发给测试者，不进入前端或仓库。

这是一轮有登录保护的小范围测试，不是面向公众开放注册，也不表示三专业内容已经完成专业审核。沿用现有技术架构；部署涉及的 P8 安全、迁移、恢复和运行检查在本轮执行，未验证项必须单列，不能直接标记 P8 全部完成。具体主机、域名、接入方式和凭据只留在忽略的本地部署目录。

## 账号与首次体验

- 新增独立 `pilot` 运行模式，本地 `local` 模式的注册／验证流程不变；两种模式不能同时启用。
- 只创建五个独立 Student Account。密码随机生成，使用现有 Argon2id 散列入库；明文仅写到受限的私有交付文件。首次初始化后，重启不重置密码、不恢复删除账号、不增加名额。
- 测试账号不使用真实邮箱。账号可被授权启用，但 `email_verified_at` 保持空值，不能伪造“已经验证邮箱”。登录、密码校验、账号锁定、会话过期、CSRF 和数据归属检查照常执行。
- 首次登录由本人确认 `pilot-v1` 条款及隐私说明，再填写背景问卷。旧 `v1` 文字保留给本地模式，不追溯改写历史同意。不能预先替测试者同意研究用途或编造推荐资料；研究授权仍可拒绝和撤回。
- 服务器拒绝公开注册、邮件验证／重发、邮件找回密码和更换邮箱请求，不能只隐藏按钮。允许登录后的密码修改；忘记密码通过项目负责人处理，不提供公开重置后门。
- 管理端不随学生站点公开。学生不能获得管理 JWT、供应商 key、服务器路径或其他账号的信息。

## 报告额度

两个额度池互不挤占：单专业 3 次，比较 2 次。每个账号最多五次新的报告生成任务；一份报告内部的初稿、结构修复、独立审阅属于同一次生成，仍最多发出三次供应商请求。

额度在创建任务的数据库事务中预占。锁定账号额度行后核对数量，创建报告版本、额度记录和作业必须同事务提交；并发点击不能超额，幂等重放不再占额。阅读、刷新、下载、打印不占额。第二个专业报告完成后生成比较，第三个专业报告完成后可以更新一次。

失败分两种：

- 尚未发出供应商请求即失败，释放预占名额。
- 已记录外部请求开始后失败，或进程退出导致调用结果不明，保留这次消耗，不自动重发。页面明确显示失败及已用额度，由负责人判断后续处理。否则反复失败重试会绕过本轮限制。

这个口径限制的是生成次数，不保证一定获得五份成功报告，也不是五次 API 请求。最多三阶段意味着五账号完整用满时，产品报告链路上限是 75 次供应商请求；这不包含另行授权的开发测试。本轮不开放用户自行重置额度。管理员重生成同样受限，不允许绕过预算。

额度耗尽不撤销已生成的报告，不丢弃已经提交的作答和反思；作业创建被拒绝时应给出具体状态，而不是令整个体验提交事务回滚或让报告一直显示生成中。旧版报告生成、AI 提示和可选追问在 `pilot` 中关闭，防止从旁路调用供应商；新版固定教学提示继续可用。

删除单份报告不恢复额度。完整账号删除时清除用量记录，保留已占用邀请名额与删除凭据，不恢复账号或重发额度。新增两张个人归属表已纳入原有删除归属检查，没有放宽未知外键的拒绝规则。

## 上线边界

新增 V13 迁移，不改写 V1–V12。生产化配置必须验证：独立数据库／Redis，回环监听，强且独立的秘密，准确 HTTPS origin，Secure/host-only Cookie，受信代理的来源 IP，独立 hostname 的执行器，关闭调试和注册入口，私有对象不在静态目录。

测试内容沿用确切 manifest 的项目负责人授权，但另记为受限测试授权，不伪装成 PUBLISHED 或专业审阅通过。默认使用全新数据库，不把本地真人报告、账号或日志上传。供应商 key 可通过加密连接传送到服务器运行环境；SSH 私钥不上传。

发版前核对域名解析、证书和适用的备案接入条件；验证五账号隔离、真实来源限流、额度并发／失败／重启、备份恢复及原有服务健康。正常回归使用离线模型；有限真实闭环单列记录，不自动扩大为容量压测。

## 运行与恢复约定

部署脚本在 `scripts/deploy`，不包含实际主机、账号密码或 API key。私有部署文件写入忽略的 `.local/deployment/pilot`，运行时秘密由 root 私有环境文件交给服务。学生前端只接收运行模式与执行器 origin。

本项目使用独立 Linux 用户、私有 Java/Node、回环 MySQL/Redis 和 systemd 资源限制；服务 JAR 路径包含发布内容哈希。低速上传可拆分公共 Maven 依赖：服务器下载后逐项核对 SHA256，重组完整 JAR 后必须再次与本地校验值一致；不能因为镜像缺文件而换版本。

依赖固定为 Temurin JRE 21.0.12.1、Node 24.21.0、MySQL 8.4.11、Redis 7.2.16。来源与校验依据为 [Adoptium](https://api.adoptium.net/v3/assets/latest/21/hotspot?architecture=x64&image_type=jre&os=linux)、[Node SHA256](https://nodejs.org/dist/v24.21.0/SHASUMS256.txt)、[MySQL 下载页](https://dev.mysql.com/downloads/mysql/8.4.html?os=2)、[Redis 校验清单](https://github.com/redis/redis-hashes)。MySQL 先核对官方下载页 MD5，再固定本地 SHA256；其他三个直接核对官方 SHA256。Temurin 镜像仅在字节校验完全相同时可用。

备份只针对本项目数据库，每日生成私有备份，保留约七天；恢复必须先到新临时库，核对迁移、账号、额度与删除记录，不直接覆盖运行库。涉及用户数据后的恢复必须补跑删除请求，不以旧备份恢复已删除账号。该备份不等于异地容灾或零数据损失保证。

模型仍使用百炼 `qwen3.8-max-0902`，启用思考，思考预算与最大输出均 32768 token，每阶段超时 15 分钟。后台串行处理报告生成任务；五个测试账号不等于已验证五人同时生成的容量。真人内容审核、目标学生体验计时、真实容量压测及全量 P8 仍需后续单列。
