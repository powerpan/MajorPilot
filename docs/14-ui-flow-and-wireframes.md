## 1. 设计范围

本文件定义可实施的低保真布局和交互状态，不锁定最终品牌字体、颜色、插画和逐像素视觉。学生端必须具有面向决策体验的产品界面；管理端沿用 RuoYi 管理框架的信息密度和导航习惯。

页面设计优先级：

1. 当前任务和主要动作清楚；
2. 报告事实、学生自述和系统解释可区分；
3. 保存、执行、生成等异步状态可理解和恢复；
4. 不用高压倒计时、适配分数或强制完成感推动学生；
5. 电脑完成任务，手机完成了解、信息填写和报告查看；
6. 加载、空、错误、离线、冲突和权限状态与正常态同等设计。

## 2. 两个前端的视觉和导航边界

### 2.1 `majorpilot-web`

面向 Visitor 和 Student，使用简洁、低压力的学习产品语言。主导航最多包含：

- 如何使用；
- 三个专业；
- 登录／个人主页；
- 账户与数据设置（登录后）。

任务进行中隐藏营销导航，避免离开和认知干扰。

### 2.2 `majorpilot-admin`

面向 Internal Operator，沿用 RuoYi 左侧导航、顶部操作区、筛选栏和表格。菜单按权限显示：

- 运行概览；
- 学生与体验；
- 任务版本；
- 推荐分析；
- 报告状态；
- 数据导出；
- 敏感操作审计。

学生端组件、Cookie 和路由不得复用管理端登录态。

## 3. 学生端路由

| 路由 | 页面 | 身份 |
| --- | --- | --- |
| `/` | 首页 | 公开 |
| `/how-it-works` | 产品如何工作 | 公开 |
| `/majors`、`/majors/:code` | 三个专业体验说明 | 公开 |
| `/privacy`、`/terms` | 隐私与条款 | 公开 |
| `/intake/:step` | 多步骤信息收集 | Intake Session |
| `/recommendation` | 注册前推荐结果 | Intake Session |
| `/register`、`/verify-email` | 注册和验证 | Intake Session／公开 |
| `/login`、`/forgot-password`、`/reset-password` | 登录和恢复 | 公开／一次性邮件令牌 |
| `/deletion-status/:receiptId` | 删除进度与回执 | 专用只读回执 Cookie，不是 Student Session |
| `/app` | Student 个人主页 | Student |
| `/app/experiences/:major` | 体验介绍或状态 | Student |
| `/app/runs/:runId` | 任务工作区 | Student + owner |
| `/app/runs/:runId/reflection` | 反思 | Student + owner |
| `/app/reports/:reportId` | 单专业报告 | Student + owner |
| `/app/comparison` | 比较报告 | Student |
| `/app/settings` | 账户和数据设置 | Student |

未登录访问 Student 路由时保存安全的 return path；登录后只能返回允许的站内路径。

首次公共写请求前获取匿名 CSRF；登录后改用绑定 Student Session 的 CSRF，页面路由不影响可读 CSRF Cookie 的 Path。邮件验证／重置从 URL fragment 读取一次性令牌后立即清除，再 POST 提交。注册完成即保存并认领问卷，邮箱验证中断时提供重发入口；不会要求重新填写问卷。

桌面和手机均使用单列，避免矩阵在窄屏变成不可读表格。

```text
┌───────────────────────────────────────────────┐
│ 返回                         第 4 / 12 步     │
│ ███████████░░░░░░░░░░░░                      │
│                                               │
│ 你目前的学习或工作背景更接近哪一类？           │
│ 这帮助我们调整解释方式，不会限制推荐专业。     │
│                                               │
│ ○ 计算机与工程                                │
│ ○ 数学与统计                                  │
│ ○ 商科与经济                                  │
│ ○ 自然与生命科学                              │
│ ○ 社科与人文                                  │
│ ○ 其他                                        │
│                                               │
│ [上一步]                         [保存并继续]  │
│ 已自动保存 12:34                              │
└───────────────────────────────────────────────┘
```

交互状态：

- 保存中：按钮仍可见但避免重复提交；
- 已保存：显示时间，不弹出打断式 toast；
- 离线：显示本地草稿状态和“连接恢复后保存”；
- revision 冲突：显示当前设备和服务器版本摘要，不能静默覆盖；
- 验证错误：靠近字段，保留其他答案；
- Intake 过期：解释原因，提供重新开始；
- 退出：明确草稿保留到何时。

情境排序提供键盘可操作的“同等优先”分组，不要求只能拖拽；三项都可放第一组。页面说明“同等想试时，我们会参考你考虑的方向和工作环节”，不暗示辅助信息会推翻明确首选。服务端拒绝跳号、缺项与重复项时保留用户输入。

```text
┌──────────────────────────────────────────────────────────────┐
│ MajorPilot                      账户与数据  退出             │
├──────────────────────────────────────────────────────────────┤
│ 继续你的专业比较                                            │
│ 推荐下一步：Data Science                [查看建议]           │
├──────────────────────────────────────────────────────────────┤
│ Artificial Intelligence   [已完成]   [查看报告]              │
│ Data Science              [未开始]   [了解任务]              │
│ Business Analytics        [未开始]   [了解任务]              │
├──────────────────────────────────────────────────────────────┤
│ 比较报告：再完成一个专业后生成                              │
└──────────────────────────────────────────────────────────────┘
```

状态标签使用：未开始、准备开始、进行中、等待反思、已暂停、已被恢复体验替换、已完成。报告另显示：准备证据／生成中／可查看／准备异常。第三项保持可选，不使用“33%／66%／100%”制造强制完成感。

空态和异常：

- 没有可用 Task Version：说明暂不可开始，保留 Recommendation；
- 报告生成失败：任务仍显示已完成，报告入口显示“正在恢复”；
- 当前有活动 Run：其他 Major 显示“暂停当前体验并开始／继续”，点击确认保留原进度后执行原子切换；
- Paused 卡片显示保存步骤和“继续”，不新建体验；Ready 改选复用目标专业入口；
- REPLACED 显示安全恢复说明与新运行入口，不显示已完成或丢弃旧答案；
- 数据删除确认后离开个人主页，转独立回执页；原主页和私有资源均不可再访问。

宽屏采用步骤栏、主工作区、帮助栏三部分：

```text

│ LumenLearn / Data Science       已保存 12:34       暂停并返回主页      │
├──────────────┬──────────────────────────────────────┬───────────────────┤
│ 1 理解问题 ✓ │ 步骤 3：探索学习行为与完成率         │ AI 帮助           │
│ 2 数据质量 ✓ │                                      │                   │
│ 3 探索关系 ● │ [任务说明和最低必要知识]             │ 当前未请求提示    │
│ 4 检查解释   │                                      │ [一级提示]        │
│ 5 写出结论   │ [图表／表格／受控代码工作区]         │                   │
│ 6 反思       │                                      │ 已使用：0 / 3层   │
│              │ [输入和判断区域]                    │                   │
│              │                                      │                   │
│              │ [运行] [保存]          [完成此步骤]  │                   │
└──────────────┴──────────────────────────────────────┴───────────────────┘
```

布局规则：

- 中间主工作区优先，左右栏可以折叠；
- 1366px 宽仍需保留可读的代码、表格和图表宽度；
- 1024–1199px 将帮助栏变成右侧抽屉；
- 不在正式任务中显示营销导航；
- 当前步骤、保存状态和退出入口始终可见；
- 提示入口显示层级，不用聊天气泡诱导持续对话。

## 10. 任务工作区状态

### 10.1 执行

- 未运行：显示操作目的和输入来源；
- 运行中：可以取消，不允许重复运行同一请求；
- 成功：显示结构化结果和运行版本；
- 验证错误：定位允许修改的参数；
- 超时：保留输入，提供安全重试；
- 引擎不可用：显示预计算降级是否可用；
- 结果过期：输入 revision 更新后，旧结果明确标为过期。

AI 任务分开标识“练习预览”和“正式评价”；正式评价显示剩余不同配置次数（最多5种），重复配置可直接查看原结果。隐藏评价只呈现聚合指标和错误类别，不提供下载答案。定义文本补充旁说明“用于表达修改理由，不直接改变分类结果”，计算变化由可选择的定义变体、示例和阈值产生。

### 10.2 保存

- 保存中、已保存、离线待同步、冲突、失败可重试；
- 页面离开前只在确有未同步内容时提示；
- revision 冲突提供重新加载和复制本地草稿，不自动选一边覆盖。

“暂停并返回主页”先等待当前草稿保存，再发送 pause；失败保留页面并提示重试，不假报已暂停。被另一标签页暂停时界面只读，并显示未同步差异；不能自动恢复。切换确认说明原任务、目标任务、保存状态；事务失败时仍显示原活动体验。主动退出与换账号前明确提示未同步草稿将被清除，自然会话过期则原账号登录后可恢复。

### 10.3 提示

- 一级提示显示概念方向；
- 二级提示在学生确认后显示；
- 三级提示再次说明仍需学生完成核心判断；
- 模型失败时使用已审核静态提示；
- 提示记录不显示“扣分”或负面标识。

## 12. Reflection

Reflection 与任务评价分开：

```text
┌────────────────────────────────────────────────────┐
│ 回顾这次体验                                      │
│ 没有标准答案，这些回答帮助你解释自己的体验。      │
│                                                    │
│ 哪个环节最吸引你？                                │
│ [选择 + 可选补充]                                 │
│                                                    │
│ 困难主要来自哪里？                                │
│ [知识] [工具] [时间] [任务方式] [其他]            │
│                                                    │
│ AI 追问（可跳过）                                 │
│ ...                                                │
│                                  [提交并生成报告]  │
└────────────────────────────────────────────────────┘
```

AI 追问明确标为可跳过。提交后先显示任务已完成，再单独展示报告生成状态。

固定必填为感兴趣环节、困难来源、继续类似工作的意愿；可选补充感受、下一次想比较的工作方式（模型迭代／数据推理／业务行动／不确定）和最多一次 AI 追问。枚举、字数与跳过语义来自 `09` §8.1。提供“暂停反思并返回”，恢复后仍在反思阶段，不要求重做任务。Closed 页面先显示“体验已完成，正在准备证据”，不能把尚未建好的快照显示为报告生成成功。

```text
│ [打印]                                                     │
├────────────────────────────────────────────────────────────┤
│ 你完成了什么                                              │
│ 事实陈述 ...                              [查看依据]       │
│                                                            │
│ 体验偏好                                                  │
│ 你的自述 ...                                              │
│                                                            │
│ 当前准备度 / 本次任务表现                                 │
│ 有界解释和限制 ...                                        │
```

状态：

- Generating：显示任务已完成和可安全离开；
- Fallback Ready：说明部分个性化解释暂不可用，但事实和成果可查看；
- Failed 且 fallback 尚未完成：提供状态刷新，不要求重做任务；
- Superseded：学生访问旧链接时跳转当前版本，不暴露历史版本。

## 15. 账户与数据设置

分为：账户安全、数据和授权、删除账户。

- 修改邮箱需要重新验证；
- 修改密码／邮箱成功后说明所有设备会退出，当前页面也要求重新登录；
- 可选研究授权可以撤回；
- 个人数据导出说明范围和准备时间；
- 删除账户不使用红色大按钮作为视觉诱导，但入口必须可发现；
- 删除确认展示立即影响、30天处理期和不可恢复结果；
- 删除确认前校验当前密码，说明本机未同步草稿清理；确认后清除学生 Cookie／本地草稿，跳转仅凭专用 Cookie 访问的删除回执页；
- 回执页只显示请求／处理／完成／需联系支持状态和时间，不暴露邮箱、报告或后台错误；凭证丢失时不承诺跨设备直接查询；
- 删除确认响应丢失时先查回执再判断成功，不要求用已撤销的登录重复确认；不提供模糊的“停用”措辞。

## 16. 管理端线框

### 16.1 运行概览

```text
┌──────────────┬──────────────────────────────────────────────────────┐
```

### 16.2 表格和详情

- 默认假名化 Student publicId；
- 邮箱和完整自由文本列默认不存在；
- 筛选条件和导出条件保持一致；
- 详情抽屉只展示当前权限允许的数据；
- 敏感查看前说明用途并产生审计；
- 任何恢复、重生成、发布和导出使用确认对话框，要求原因；
- 不提供修改学生答案和直接编辑报告的控件。

### 16.3 任务版本

任务版本页展示 Major、version、manifest hash、data hash、审核人、状态和发布时间。发布前显示十项内容验证结果。管理端不提供任意在线文件编辑器。

## 17. 通用页面状态

每个数据页面都需要：

- 初次加载骨架，不伪造内容；
- 真正无数据的空态及下一步；
- 权限不足，不泄露资源存在；
- 可恢复错误和重试；
- 不可恢复错误及安全返回路径；
- 离线或网络较差状态；
- 会话过期并在登录后安全返回；
- 数据版本过期或并发冲突；
- 操作成功的就地确认；
- `prefers-reduced-motion` 和键盘焦点状态。

## 18. 可访问性和内容规范

- 键盘可完成表单、工作区操作、提示和报告展开；
- 焦点顺序与视觉顺序一致；
- 输入具有可见 label、错误说明和关联描述；
- 图表提供文本摘要和可读取数据表；
- 状态不只依赖颜色；
- 代码、英文术语和中文说明的语言标记准确；
- 最小点击区域适合触屏；
- 弹窗打开后管理焦点，关闭后返回原触发点；
- 保存和执行状态使用 `aria-live` 的克制提示；
- 不用“你不擅长”“低能力”“失败者”等评判性文案；
- AI 内容明确标识为系统生成解释，并保留边界说明。

## 19. 页面设计验收

1. Visitor 能在手机完成 Intake 并在注册前看到真实 Recommendation；
2. 注册或验证失败不会丢失 Intake；
3. Student 主页准确区分任务状态和报告状态；
4. 打开体验介绍不会被记为正式开始；
5. 1366px 桌面可以同时使用步骤、核心工作区和帮助；
6. 1024px 能通过抽屉访问帮助且主工作区仍可用；
7. 手机不会进入残缺任务编辑界面；
8. 离线、保存冲突、执行超时和模型失败都有恢复路径；
9. 报告清楚区分事实、自述、解释和限制；
10. 管理端默认不显示邮箱和敏感自由文本；
11. 管理员界面不存在修改学生答案或直接编辑报告的入口；
12. 所有关键流程可以只用键盘完成；
13. 空态、错误态和无权限态不泄露其他学生数据；
14. 任务和报告页面不会出现专业适配度总分；
15. 最终视觉设计可以替换颜色、字体和品牌素材，但不得改变本文件的流程、状态和职责边界。
