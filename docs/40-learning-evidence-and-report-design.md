# 方法过程证据与新手可读报告

> 2026-09-24，当前报告设计基线，已获准实施；实现与 Schema 发布状态见[42 台账](./42-method-led-implementation-ledger.md)。关联：[38 总体设计](./38-method-led-experience-redesign.md)、[39 案例](./39-guided-major-case-specifications.md)、[41 Excel](./41-excel-download-and-local-results.md)。

## 1. 报告要回答的问题

报告帮助学生理解“我怎样走过这条方法路线”，不是根据最终文本推测脑内过程。报告仍分别说明本次表现、当前需要的支持、本人体验偏好，不输出综合分数或适配结论。

每项关键解释都应说明：

- 在做哪件具体的事；
- 学生确实写了什么／选择了什么；
- 哪部分合理、哪部分与题目或数据不符，为什么；
- 提供了什么帮助，后续提交是否出现相关变化；
- 还不能确定什么，以及下一步可怎么尝试。

“最早出现问题的记录”不等于“从这里开始不理解”。“看过讲解后答案变正确”也不证明讲解是唯一原因，更不能外推学习速度或潜力。

## 2. 新增证据单位与记录时机

领域定义见[CONTEXT](../CONTEXT.md)。下列定义逻辑职责，不与数据库列或 API 字段一一同名。现已接入方法版实现；实际合同见 [openapi-method-flow](../contracts/openapi-method-flow.json)，发布和验收状态见[45](./45-method-led-release-verification.md)。

| 对象 | 最小保存内容 | 允许证明什么 |
| --- | --- | --- |
| Method Path | 路线版本、节点、检查点、必要概念、依赖、合理异解、评价准则版本 | 任务期望和教学范围，不证明学生表现 |
| Learning Attempt | Run、检查点与变式ID、尝试序号、明确提交的回答快照／revision/hash、提交序列、角色（初次／修订／新情境） | 学生在这个条件下提交过什么 |
| Learning Support | 内容ID／版本／hash、基础介绍或提示层级、送达／打开记录、关联尝试 | 提供过哪些材料，不证明已读或已理解 |
| Recovery Baseline | 固定资产／参数／验证结果引用、选择使用的提交序列、受影响节点 | 后续判断是在系统给定结果上完成 |
| Local Result Submission | 工作簿版本／hash、处理规则与范围、行ID或分组、数值／单位、解释、核对结果 | 本地自报和可复算部分，不证明本地操作过程 |
| Reflection | 已有固定反思字段与明确自述 | 本人表达的兴趣、困难、帮助体验 |

只保存显式“提交这一小步／保存修改并继续”形成的有界尝试，不把每次自动保存或键盘输入都送模型。草稿机制继续保留，但不作为学习过程证据。每检查点最多初次与一次修订；每专业一个新情境检查，固定题目示例可复看。技术失败重试不增加逻辑尝试。

需要服务端校验归属、当前Task Version、revision和幂等键；修改必须新增记录，不覆盖首次尝试。客户端时间和本地Excel自述不能作为可信行为时间线。离线先保留待同步状态，服务端接受后才算提交；过期revision就地提示并定位，不猜测离线操作顺序。

Run关闭时，同事务冻结最终答案、明确提交的相关尝试、已提供支持、恢复基线、回填及核对、反思、方法／题目／规则／文件版本引用。异步快照只读取这个冻结集合。并发关闭、双标签页、暂停切换、重启、删除竞态及幂等按现有归属栅栏扩展。

模型只接收白名单内容；不发送账户、完整点击流、无关草稿、本地路径或完整工作簿。日志只保留状态和必要元信息，不记录学生全文或供应商思维链。新增记录纳入现有导出、删除和留存政策，不能因“学习研究”默认永久保留。

## 3. 评价对象与支持条件分开

每个检查点的内容判断仍是对当前题意的有限判断，而不是能力等级。可以沿用已有四种含义，但展示成更直接的解释：

| 内容判断 | 学生可见表达 | 必须满足的证据条件 |
| --- | --- | --- |
| 支持 | 这一步的理由说得通 | 当前题要求已满足，允许有可选改进 |
| 部分支持 | 还差一个关键说明 | 明确指出本题必需而确实缺少的内容 |
| 需修改 | 这里有一处需要改正 | 指出具体矛盾、错误数值或不成立的推断 |
| 无法判断 | 这次还看不出你的想法 | 没有相关理由、未回答或材料不足；不猜动机 |

独立保存支持条件：基础讲解已提供、额外提示已提供、用了恢复基线、存在新情境响应、没有记录。支持条件不能折算分数。没有提示记录只代表平台未记录该类帮助，不能证明没有外部帮助或完全独立完成。

允许生成的变化描述及限制：

- 初次理由已满足要求：可写“第一次提交时已能解释这一步”，不得写“天生擅长”。
- 讲解后修订：对应概念确实改正，才写“这次修改补上了……”。保留帮助条件，不称已经长期掌握。
- 新情境也给出合理解释：写“在这道不同的小题中也运用了这个想法”。不是一般化迁移能力认证。
- 同概念仍有问题：写“这一处仍需要进一步练习”，指出具体句子。
- 初次无关，后续没有提交：只写“目前没有足够内容判断”，不写“乱答／不认真”。
- 前后答案相互矛盾：并列准确引用，解释矛盾，不能任选对／错的一句概括全部。

## 4. 依赖关系与卡点定位

每个检查点冻结其上游依赖，区分硬依赖与可独立评价部分。例如BA后续比例依赖分母，但提出一项相关行动的理由不一定依赖比例算对。

定位顺序：

1. 先检查任务是否提供了必要概念和资料。若缺少，标记内容设计问题，不归咎学生。
2. 将明确错误绑定到具体题目、原话、计算条件或结果。
3. 若下游使用了同一错误结果，标记“可能受前一步影响”；只有依赖证据充分时说明联系，不按出现次数重复计错。
4. 提供已核对的中间结果后，另看下游表现；不将恢复数据算作学生成果。
5. 如果没有这种恢复或新题证据，保持“还不能区分计算困难与后续理解困难”。

报告不能声称知道准确的心理卡住时刻。后台可按概念查看高频问题，但点击、停留、下载、重试次数是 Product Event，不自动转成理解证据。只有相同任务／题目版本、支持条件、提交条件可比时才汇总；学生自选求助造成的选择差异不能解释成帮助效果。

## 5. 生成流水线

采用“规则保证可核查事实，模型解释具体思路，再独立审阅”的分工。不是让大模型对最后几个文本框自由总结。

1. **冻结输入**：得到版本一致的题目、公开材料、全部必要最终回答、三个关键检查点尝试及相关上下文。若输入完整性失败，不发布伪报告。
2. **复核事实**：服务端重算可支持的数据处理／分组／指标，保留本地回填是否可复算的状态。规则不预写学生能力或兴趣结论。
3. **整理过程依据**：按检查点形成初次回答、支持、修订、新情境、上游依赖及恢复条件；某项缺失就是缺失。
4. **生成分析初稿**：高能力模型读取上述完整相关上下文，逐项给出判断依据，找出少量重点；内部覆盖所有关键检查点和需要评价的最终开放回答，不为缩短首屏漏掉重要错误。
5. **可读稿与独立审阅**：初稿本身按新手语言输出；另一轮同时审阅事实、合理异解、来源、因果边界和可读性，返回完整最终稿。不是仅把结论变得更肯定或把术语替成近义词。
6. **发布前确定性校验**：Schema、引用和原话、数值单位、覆盖、版本、归属、禁用分数／适配结论、已改正问题的状态一致性。
7. **保存不可变 Report Version**：记录模型、提示／准则／方法／数据版本及调用状态和用量；当前版本切换原子化，既有可读版本在失败时保留。

上述流程是设计，不宣称模型分析的语义可以完全用规则证明。需要独立内容质量评测和真人可读性验收。模型选择保持质量优先，不为节省成本静默换成低能力型号；不在本文指定一个未经当前账号和内容验收的具体型号。

方法版实现沿用“初稿＋必经审阅、初稿最多一次结构修复”模式，总计最多3次外部请求、单次最多900秒、总计2700秒；模型或合同调整必须重新验收，不能叠加无限可读性改写循环。这是异常上限，不是响应时间承诺。普通测试不调用付费模型，语义测试使用独立合成案例入口，不等于容量压测。

若分析或审阅失败，可显示已有任务记录／本人作品并明确“深入分析暂未完成”，不得用通用赞美冒充个性化反馈。原始证据缺失时不能通过套模板降级绕过。不得展示未经校验的流式半份分析。

## 6. 概念输出合同

以下描述字段职责；新运行使用独立的 [method-report-v1](../contracts/schemas/method-report-v1.json) 合同，不改变旧 report-v1／report-v2 的历史读取行为：

| 组 | 内容 | 来源要求 |
| --- | --- | --- |
| 体验概览 | 方法、成果、主要合理判断、重点问题 | 作品／题目／具体尝试引用 |
| 方法节点 | 节点目标、准确原话、判断、白话解释、下一步、可选例子 | 问题版本＋回答＋必要结果引用 |
| 变化记录 | 初次／修订／新题、所提供帮助、变化与未知 | 至少两项可比较提交才能写变化；独立列支持条件 |
| 依赖与恢复 | 哪些结果来自系统、哪些问题可能传递 | 依赖版本、基线及使用记录 |
| 本人感受 | 兴趣、困难、继续意愿 | Reflection，不由对错代推 |
| 专业连接 | 任务体现的工作方式和未覆盖部分 | 审核过的方法说明，不吹嘘就业收益 |
| 下一体验 | 固定规则结果及可解释理由，自由改选 | 既有NEXT结果；模型不得擅改排序 |
| 限制与来源 | 合成材料、时长参考、支持、本地未观测、模型局限 | 当前Run真实条件，不一律写完全独立 |

每条解释需要机器可核对的来源键，但学生正文只显示自然语言题目、原话和相关结果，来源键不直接呈现。原话逐字保留；新写的示例明确标为例子，不改写后再声称学生这样写过。

实现中的 `calculationConditions` 独立于模型分析，由冻结记录直接生成。它核对最后一次填写的哈希与同专业、同步骤的记录，显示数值一致／不一致／无法复算／版本不同／尚未核对，并明确是否记录过网站计算帮助。未匹配的旧核对不能证明修改后的值；没有帮助记录也不证明独立完成。报告概览就地展示此说明，非成功状态默认展开，打印全部展开。旧不可变报告没有此字段时保持可读，不补造历史核对。

## 7. 学生页面与原报告责任映射

首屏设计目标：约120–200字的概览，加最多3条重点。数字是可读性预算，不是为了凑字数的Schema最小值；复杂依据放到对应节点，不删除关键条件。

| 新阅读层 | 原报告信息责任 | 默认显示／可展开 |
| --- | --- | --- |
| 这次你做了什么 | 体验概览、完成内容、方法及成果 | 默认显示；任务版本等元信息次要呈现 |
| 沿着过程回看 | 当前需要支持、本次表现、具体作答与依据 | 最重要问题和变化默认显示；全部节点、完整计算展开 |
| 这与专业选择有什么关系 | 体验偏好、专业工作方式、另外两个专业差异、下一建议 | 默认显示；兴趣不足则说明不能判断 |
| 全程必要提示 | 证据与结论边界 | 一句总体边界＋相关段落就地条件；详细来源展开 |

保留编辑式单列正文与清楚的章节跳转，不新增评分仪表、满屏卡片或红绿能力等级。方法路线使用文字状态和准确定位；不能仅用颜色传达对错。打印须包含关键依据和支持条件，折叠不能导致纸面缺内容。

反馈段的最小顺序是：**当时在解决什么 → 你的原话 → 哪一点说得通／需改正 → 为什么 → 可以怎么做**。若已经修改，紧跟修订结果，不在最后总结时继续指控已改正错误。没有问题时不强凑缺点；资料不足时不强凑优点。

语言规则：

- “分开观察、原因假设与未知信息”改为“我们知道发生了什么，但知道原因了吗？”
- “形成有目标和护栏的小范围试验”改为“先试一个办法：怎么看有没有用，什么时候该停？”
- 先讲意义再讲术语，例如“同时留意支持团队是否多了很多工作，这类检查叫护栏指标”。
- 一段只解释一个主要问题；不连续堆叠口径、混杂、成熟窗口等未解释词。不能把所有专业词机械替换而损失准确性。
- 数字旁明确是谁、什么期间、除以什么、单位是什么；“下降23个百分点”不能被通俗化成“少了23%”。
- 避免“分析骨架、合法工作线、当前已足够、分层证据”等内部评语。
- 不用鼓励遮盖无关答案；也不用“你没有商业思维”等人格化结论。

## 8. 报告示例：只有存在这些记录时才可这样写

以下是说明结构的假设教学过程，不是当前真人记录或真实模型输出：

> 你选择先改善报名后没有开始上课的问题，并给出了相关的数据理由。
>
> 第一次设计验证时，你写“提醒后开课比例变高，就证明提醒有效”。这还不能排除人群或时间变化。
>
> 在提供两组比较的例子后，你的修改增加了同一时期的未额外提醒组。在后面换月份的小题中，你也指出两批人可能不同。就这两次回答看，你已经能在这些情境中解释为什么需要比较；是否能独立用于其他问题，还需要继续尝试。
>
> 你表示更喜欢提出行动、不太喜欢整理数字。这是你的体验感受，与某一道题是否答对分开看。

真实记录若只有最终答案，删除整个“第一次／看过例子后／后面小题”叙事，明确没有这些证据。

## 9. 比较报告

按共同的可解释问题并排呈现：做了什么、哪类工作愿意继续、哪里需要知识或工具支持、帮助后在具体题目有什么表现、尚不能比较什么。每专业引用自身方法与来源版本，不横比正确题数、用时、提示数、评价集准确率或新情境难度。

若同一共享情境先前已见过，报告说明可能受到前次体验帮助；不声称三专业是在相同先验条件下测得。不基于当前检查状态新增推荐权重，NEXT规则沿用；若将来要改变推荐，需另行设计、确认和验证。

## 10. 质量案例与验收

| 案例 | 期望结果 |
| --- | --- |
| Q01 初次合理、未求助 | 具体说明合理依据，不写无外援或稳定掌握 |
| Q02 错误后修订合理 | 说明确切变化，原错误不继续被列为未修正 |
| Q03 只复制示例，新情境不成立 | 分别呈现，不能称已经能独立应用 |
| Q04 无关或空泛答案 | 说明缺少什么，不推断懒惰或故意乱填 |
| Q05 合理异解 | 尊重所选重点、数据处理和行动，不强制标准答案 |
| Q06 上游分母错误、下游受影响 | 合并说明依赖，避免重复归因；缺恢复证据时保留不确定性 |
| Q07 使用恢复基线后合理 | 承认后续推理，同时注明中间结果由系统提供 |
| Q08 本地填报恰好正确、无操作记录 | 只能说数值与复算一致，不能证明Excel熟练或独立操作 |
| Q09 非支持的本地处理方法 | 数值暂不能核对不等于答错；仍可有界评价解释 |
| Q10 未做迁移题／旧版记录 | 不伪造学习变化；仍能给有限报告 |
| Q11 同一概念前后矛盾 | 并列依据、说明矛盾，不择句捏造统一结论 |
| Q12 教学材料缺必需概念 | 内容缺陷进入待修，不把未教授前提当学生缺陷 |
| Q13 跨专业任务难度不同 | 不用检查结果产生专业排名或学习速度比较 |
| Q14 数值／时窗／次数单位陷阱 | 保留分母、个人28天与批次范围，目标与效果分开 |
| Q15 注入文本／资料归属错误 | 当待分析资料，拒绝越权来源和输出指令 |
| Q16 模型失败／旧报告存在 | 保留可读旧版；不发布未经审阅的初稿 |

验收分开：工程合同与隐私／数据数值正确性／模型语义公允性／新手可读性。Q01–Q16 定义验收场景，表格本身不是通过证据；实际批次、代理语义复核与尚未执行的真人门禁见[45](./45-method-led-release-verification.md)。可读性试用采用38的复述问题，不以“模型自评通俗”替代真人理解。
