## 3. 不改变产品方向的工程取值

- 密码使用独立 Student Argon2id 策略，不复用 RuoYi 管理员的 20 字符上限；15–128 个 Unicode 字符，19 MiB 内存、2 次迭代、并行度 1。
- 验证邮箱令牌 24 小时、重置令牌 30 分钟，数据库仅保存哈希；验证不自动登录，重置撤销所有会话。
- 注册与 Intake 认领在同一事务中完成；SMTP 在事务提交后发送。发送失败不丢失已认领资料，提供重发／正常登录恢复，不将明文邮件令牌写入作业或日志。
- 注册认领后撤销 Intake 凭证；认证先于幂等重放。已失去 Intake 凭证的重试不重新获得资料读取权，使用明确的登录恢复指引；不重放 Session、密码、原始令牌或 Set-Cookie。
- `local` 运行正式 P1 API，`p0` 独立保留合成技术探针；不同时启用互相冲突的认证路由，不把合成主体识别为真实 Student。
- 邮件仍进入本地 Mailpit，不声称外部邮箱或生产 SMTP 已接通。隐私与条款是版本化本地产品说明，不是已完成法律审核的公开政策。
- 可选研究授权默认不勾选，拒绝／撤回不影响核心流程。
- 用户 2026-09-20 明确确认本轮规则解释即可，AI 润色单列后续增强。运行路径使用真实结构化理由；可选端口的模拟失败／回放测试只是降级测试，不是供应商业务接入。本轮未新增百炼／DeepSeek 付费调用。

## 4. 设计接缝的明确解释

- 第 12 页允许跳过：渠道空值规范化为 `DECLINED`，困惑可空；“10 个必填”按页面计，不按矩阵格子计。
- 匿名 Profile 增加 `sourceDraftRevision` 唯一性，同一提交版本不会因换幂等键产生重复记录；新答案提交创建新 Profile，不覆盖旧答案。
- 错误统一为 `error + meta`；revision 冲突的安全版本提示使用显式 `error.details.currentRevision`，不夹带他人或完整服务器答案。
- 7 天续期只来自匹配凭证的有效读写，失败与越权不续期；过期未认领资料的最小清理属于 P1，完整账户删除和导出不在本阶段冒充完成。
- 客户端只提交答案与观察事件白名单；排序键、推荐项、理由、业务事件和主体由服务端计算。后台分析记录不作为用户可见的能力评分。
- 设计文档的 snake_case 是逻辑问题名；实际 JSON DTO 使用 camelCase，见 `contracts/examples/p1-intake.json` 与 `openapi-p1.json`。
- 页面观察要求连续可见至少 1 秒，传入整数 `visibleDurationMs`；它不变成可信业务事实或任意分析属性。后端拒绝小数／字符串转整数、数值转枚举／凭据字符串的隐式转换。
- 成功登录清除旧匿名 Intake／public CSRF Cookie，但不认领、转移或删除其数据库资料；未认领数据仍按 7 天规则留存。退出／认领／换身份通过无 PII 的跨标签通知失效本项目缓存，身份 epoch 阻止迟到结果复活旧账户或答案。
