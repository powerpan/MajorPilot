# 报告 v2：完整上下文与作答分析

2026-09-22（始于 2026-09-21）。状态：工程实现与回归已完成，模型语义门禁未通过，尚未切换主站或提交推送。本轮是用户明确授权的报告质量修订，不代表 P8 或公开发布完成。

## 问题与范围

真人报告确实调用了百炼 `qwen3.7-plus`，但六组 BA 开放题被过滤，模型只选择固定文案，且思考模式关闭。对照探针证明：只把合理开放题换成明显乱写，模型仍看不到原文，默认 AI 路径正文不变。以“调用成功、合同合法”替代“有分析价值”的验收不足。

本轮明确取代 [P6 工程合同](./31-p6-engineering-plan.md)中 v1 的任意分析禁止、45 秒外部预算和仅目录输入约束；旧版本仍按旧合同校验。保留固定 NEXT 规则、无总分/适配排名、身份/来源/发布栅栏、原始答案不可改写和私有报告访问。

## 输入与来源

- 使用原关闭记录绑定的任务题目、步骤字段、必要公开材料和版本化评价准则；不是把整个仓库、日志或后台对象发给模型。
- 包含原答案、服务端核算结果、支持条件、个人反思以及相关背景白名单；待评价答案明确为学生自述/分析，不当作世界事实。
- 旧 Evidence Snapshot 已有的分析条目继续保持 `UNVERIFIED / claims=[]`。v2 可以评价它，但不能用它发布未经验证的事实。
- 旧提取器遗漏的答案使用 Frozen Response Reference：重新校验原 revision、关闭向量和 hash，再纳入版本固定的上下文。不以无关执行证据冒充答案来源，不修改旧快照。
- 模型中的来源引用受白名单约束；学生页面显示问题、本人原话和解释，不显示内部证据 ID、管理员信息、提示词或密钥。

## 输出与质量边界

v2 在原九节体验报告／八节比较报告之外增加可读的作答分析：总览、每专业的当前准备／任务推理／下一练习、逐题引用与反馈，以及有来源的跨专业比较。

逐题分析包含：原文引用、`SUPPORTED / PARTIAL / NEEDS_REVISION / INSUFFICIENT`、原因、改进建议与示例。旧通信合同至少覆盖每个有开放题答案的步骤，新预绑定合同逐一覆盖全部已回答的步骤开放字段；合理异解不能因为不同于示例答案就判错；缺信息不能假装读出学生动机。禁止从一次作答推断智力、人格、稳定能力、录取概率或专业适配度。

改进建议和改写示例与正文适用相同证据标准，不能借“举例”引入未经支持的结论。已在结构化选择或材料中提供的信息不能再判为未填写；未解释某个值的依据和根本没有提供该值是不同问题。没有统计检验不能声称显著，没有样本设计和容量资料不能保证试验足够、成本低或负荷可承受。未见预期改善不等于整个原因假设被证伪；试验建议须说明比较方式、观察窗口、混杂和不确定性，不能用任意小样本及目标值直接推出扩大实施的决定。总览与逐题评价还须保持一致。

服务器校验字段、长度、引用归属、原文匹配、步骤覆盖、来源版本和受限内容；这不是形式化证明分析正确。语义正确性必须另经质量样例和人工阅读核验。模型失败时明确分析不可用，不用固定句子假装完成分析。

逐题评价准则采用独立版本。`report-assessment-rubric-v2.1` 进一步区分 BA 任务中的比例与绝对人数、原因机制与干预效果、同期随机与时间交替比较、运营目标与干预效果判断；包含不依赖某个测试答案的通用错例校准。前面步骤不被要求提前完成后续试验设计，合法选择也不因未选最大降幅而判错。旧 `v2` 准则文本原样保留，来源重验按报告中冻结的准则版本重建，未知版本或只改版本标签会被拒绝。

`report-assessment-rubric-v2.2` 为 BA 增加紧凑的 `ba-aggregate-lineage-v1` 派生事实：按冻结选择和公开原始行计算各窗口总体、课程、渠道计数，以及真实交叉行中的未启动分布，并与已验证的分组执行结果核对。互斥完备的分组应先加计数再算总体率；可推导信息不是未知，个体原因、支持触达与干预效果仍未由聚合数据给出。这个投影不依赖开放答案质量、不新增伪造证据或固定评语。旧 v2/v2.1 不增加字段，已有上下文、来源、输入、目录、模型输入及审校输入的固定哈希均须保持。

`report-assessment-rubric-v2.3` 已补齐课程×渠道双窗口计数与差值，并区分材料直接提供、确定性可计算及未记录的信息。它解决的是已知信息的呈现，不预写学生评价，也不把渠道构成变化解释成增长原因。交叉事实追溯到原材料和冻结窗口，不拿课程边际执行结果冒充交叉来源；变更前先保存 v2.2 全链固定哈希，旧三个版本的重建保持不变。DS 的 `task.analysisFrame` 同样只投影真实执行、冻结选择和公开字典：明确区分分布变量、配对 x/y、有效分母、纳入边界与当前分层字段，不把已观测但未控制的变量称为未观测。

## 模型基线

质量优先，不自动路由或为节约费用降到轻量模型。报告使用独立配置，避免连带改变即时提示的延迟策略。

2026-09-21 官方资料列出 `qwen3.8-max-0902` 为高能力推理模型，支持长上下文和结构化输出。已在现有北京兼容端点用同一账号完成单次合成探针：HTTP 200，思考内容确有返回，JSON 完整结束；这只证明账号可用，不代表完整报告质量通过。[模型目录](https://help.aliyun.com/zh/model-studio/text-generation-model) · [思考模式](https://help.aliyun.com/zh/model-studio/deep-thinking) · [结构化输出](https://help.aliyun.com/zh/model-studio/qwen-structured-output)

新报告采用初稿生成与必经独立审校，租约仍独立续期；初稿最多一次结构修复，审校不修复或重试，合计最多三次外部请求、总预算 2700 秒，单次最多 900 秒。v2 首轮超时或限流不额外重发。只记录模型、状态、用量等元数据，不保存供应商思维链。普通构建和回归不触发付费调用，真实质量评测单列明确入口与次数，不是容量压测。

v2 使用服务端流式接收，思考分片即时丢弃；仅累计最终分析文字，页面仍等待完整校验后一次发布，不展示未经验证的半份报告。须收到正常结束原因、结束标记和 HTTP 完整结束；断流、供应商错误或部分回复不会伪装成成功。单帧上限 256 KiB、总传输上限 16 MiB、最终文字默认上限 1 MiB，整个请求共用一个截止时间。旧 v1 保留非流式协议。

报告独立环境项为 `MP_REPORT_AI_MODEL`、`MP_REPORT_AI_TIMEOUT_MS`、`MP_REPORT_AI_MAX_OUTPUT_TOKENS`、`MP_REPORT_AI_THINKING_BUDGET_TOKENS`、`MP_REPORT_AI_MAX_RESPONSE_BYTES`、`MP_REPORT_AI_OUTPUT_FORMAT`。百炼基线分别为 `qwen3.8-max-0902 / 900000 / 32768 / 32768 / 1048576 / JSON_SCHEMA`，启用标志仍是 `MP_REPORT_AI_ENABLED`。真实完整 BA 首次试验达到旧 180 秒超时，先提高至 600 秒；随后完整 AI 审校又实际触及 600 秒，因此在保留模型、完整输入及三次调用上限的前提下提高至单次 900 秒、总计 2700 秒，容纳完整的修复与审校。45 分钟是极端上限而非通常耗时，已有完整案例约 10–17 分钟，尚需根据更多实际延迟做产品优化。密钥只读忽略的本地环境文件，不能进浏览器 bundle。

早期诊断使用思考预算 16,384。随后按质量优先要求改为 32,768；官方参数表将这一范围映射为 `xhigh` 思考力度。只发送 `thinking_budget`，不同时发送互斥的 `reasoning_effort`。这提高推理预算与档位，但不能替代质量审读，也不能据不同配置的试验推断唯一改善原因。[官方参数说明](https://help.aliyun.com/zh/model-studio/qwen-api-via-openai-chat-completions)

早期 P0 的 JSON Schema HTTP 400 是旧模型／请求的验证记录，不代表新模型永久不支持。对当前 `qwen3.8-max-0902` 重新做了一次无真人数据的小样测试：思考 32,768、流式、`json_schema`、`strict: true` 和嵌套字段／数组约束同时通过，HTTP 200、约 18 秒；这仅证明接口能力。v2 百炼默认改为按报告类型固定的严格结构，体验报告的跨专业数组必须为空；仍执行完整本地结构、来源、原话和内容校验，不能依赖供应商保证语义正确。旧 v1 维持其输出协议，其他格式只可显式选用，不在失败后静默降级。[结构化输出说明](https://help.aliyun.com/zh/model-studio/qwen-structured-output)

完整合同首轮收到 HTTP 400，独立小请求定位到供应商不支持数组 `uniqueItems`。因此仅在供应商结构投影中去掉这一关键词，原始合同和本地重复值校验不变；这是一份受支持的结构子集，不宣称与发布合同完全等价。DeepSeek 适配仍保留，但严格 Schema 能力未验证，默认使用显式 JSON Object；切换供应商时需同步选择相应报告模型和输出模式并重新做质量验收，不能把百炼结果视为其他模型也已通过。

### 显式质量评测入口

`scripts/report-analysis-spike.mjs --check` 不调用供应商。付费测试需要 `--live --cases <明确案例列表> --run-id <新唯一标识>`，默认使用本地选定的报告供应商；每个案例必须经历初稿及审校，初稿可有一次结构修复，最多三次请求、2700 秒，最多六个案例。普通测试会关闭该入口。即使编译失败或超时，运行标识也被占用，不能默默重发。旧试验仍按当次冻结的 1200 秒总预算记录，不追改在途预算。

案例为 `ba-good`、`ba-concept-errors`、`ba-unrelated`、`ba-alternative`、`ai-metric-error`、`ds-causal-error`。BA 四组仅改变开放题文字；数值选择、执行和反思保持相同。测试使用真实题目、公开材料、生产评价准则与合成学生作答，不使用真人账户。结构合法和关键词信号只是筛查；0600 临时输出须进一步审读，确认解释引用了实际问题、没有把合理异解误判为错，也没有用固定赞美掩盖无关作答。

首次长上下文流式诊断使用同一合成 BA 输入和模型，完整返回约 193 秒，输入 16,500 token；原话、来源和真实 Java 核心校验均通过，但人工审读发现试验设计、信息缺失判断和过度断言问题，因此没有计为质量通过，也未写入真人报告。早期两次非流式返回的通用结构错误没有保留最终内容，不能事后归因于某个字段；另有超时。流式成功也不能单独证明旧失败是 HTTP 协议版本造成的。诊断只保留合成最终内容，不保留供应商思维链。

一次 `xhigh + JSON_OBJECT` BA 样例完整返回约 404 秒，输入 16,761、输出 15,706、其中思考 9,367 token；因单专业报告错填跨专业分析被拦截。人工复核还发现局部算术、示例改变原合法选择及步骤范围问题，因此没有放行。该轮唯一修复在途时，已核验进程身份并停止合成测试，保留防重发记录与已接收结果；未执行该批其余案例，也未停止主站或改写真人数据。后续严格结构轮次单独计数，不能把中断轮次记为通过。

修复供应商结构子集后的完整 BA 严格结构请求一次成功，约 518 秒，输入 17,017、输出 20,370、其中思考 13,907 token。11 条逐题原文与来源通过本地校验，但审读仍发现示例中无依据的低成本判断、将已有渠道构成描述为未知等问题，故仍未计为语义质量通过或更新真人报告。开始以同一输入和评价标准对照 `deepseek-v4-pro` 的 `max` 思考模式；此时只是独立合成测试，不自动修改应用供应商，也不在失败时静默降级。DeepSeek 官方说明其 Pro 支持长上下文、思考模式和 JSON Object；实际质量仍必须单独验证。[DeepSeek 模型](https://api-docs.deepseek.com/quick_start/pricing/) · [思考参数](https://api-docs.deepseek.com/guides/thinking_mode/)

DeepSeek 首次同题对照约 210 秒，输入 16,589、输出 13,958、其中思考 10,348 token；结构与引文通过，题目阶段判断更公允，但仍有比例方向和因果否定错误，未放行。随后使用旧输入及此合成草稿进行了独立审校改写原型（约 232 秒，输入 20,629、输出 17,484，其中思考 13,559 token）。原型修正了已知主要错误，并通过真实 Java 结构、原话、来源及覆盖校验，但仍有少量无参照的措辞；它不是生产发布门，也没有保存到真人报告。

局部准则 v2.1 的一次直接生成约 285 秒，输入 17,315、输出 18,572、其中思考 14,212 token；旧比例及因果错误有所改善，但仍把可由分组汇总得到的观察误判为引用来源错误，并将历史基线目标悄悄改为同期实验差值。未计为语义质量通过，也未写入真人报告。

首次接入必经审校后的 BA 合理作答样例共三次请求，约 610 秒（初稿、一次引文结构修复、独立审校）。最终稿结构及引文通过，保留了历史目标和合法群体选择，但仍错误否定了同窗口分组计数汇总的总体观察，并把材料中可计算的未启动者分布当作未知，因此语义验收失败。该批第二例的初稿已返回、审校在途时停止了专用测试 JVM，审校结果记为未知，不重复该运行标识；其余四例没有发起。没有更新真人报告，也没有停止主站。下一轮在服务端补充通用的可复算聚合依据后，先验收合理作答和概念错误两例，再继续其余案例。

v2.2 使用 DeepSeek 的两例进一步对照中，概念错误样例两次请求约 320 秒，最终稿能准确识别百分点/相对变化、分母、群体素质归因、唯一原因、保证效果、前后比较因果与支持联系单位，语义验收通过；来源说明及摘要仍有措辞优化空间。合理作答样例三次请求约 545 秒（含一次概览引用修复），最终仍错误否定合法分组汇总引用，并把历史目标 +2 个百分点改成同期组间差值，因此失败，不能据另一个案例通过就放行整个模型。随后用相同 v2.2 输入在百炼旗舰进行合理答案和合理异解对照，未改变主站配置或真人报告。

同时补齐一条原来提示遗漏的结构合同：每专业分析的引用须含该专业至少一条原作答来源，不能只引用验证结果。这只是把已有验证要求明确告诉模型，不自动添加或伪造引用；后续评测使用补充后的提示。隔离评测使用冻结 classpath，普通编译和回归不会改变在途请求使用的代码。

百炼 v2.2 合理异解样例两次请求约 919 秒，独立审读通过：保留合法优先策略与同期随机对照，历史目标 +2 个百分点没有偷换为组间差值，未编造成本或效果保证；“运营目标示例”等措辞仍可优化。合理作答样例三次请求约 1044 秒，数值、历史目标与合法总体观察改善，但仍把后续步骤的完整性要求用于降低前面合法业务范围的评价，未放行。后续窄修订明确 `SUPPORTED` 不等于完美，`PARTIAL` 必须指出本题必要条件的缺口，仅有可选进阶建议不能降级；同时把单专业供应商结构限制为一份专业概览，重复专业独立返回安全诊断，不放松引用验证。正在运行的其他案例保留原冻结版本，修订后结果另行记录。

随后同一旧冻结构建的无关作答案例在审校中重复输出专业概览，AI 案例则为已有原作答编造新的 Frozen Response Reference，均被本地校验拒绝，没有最终可发布报告。后者不是缺少原文，而是模型没有沿用真实来源标识；不能自动补引用后冒充通过。最新供应商结构将实际输入的来源与专业限制为枚举，审校也只从原始输入生成枚举，不从草稿生成。引用属于哪个专业、哪道题及是否匹配原文仍由本地校验，枚举本身不能证明这些关系。另补通用审校要求：声称单变量试验时只改变一个独立因素，组合改动不得伪装成单因素因果判断。

实际来源枚举版的 AI 初稿通过结构与来源校验，但审校在 600 秒触及单次超时；合理作答初稿在正文回显内部 ID 被拒绝，一次修复后通过，但审校仅余约 332 秒，触及旧 1200 秒总预算。两例均无最终稿，不计语义通过，也不重发原运行标识。除提高有界时间预算外，初稿提示也明确面向学生的新写正文不可回显内部键名/ID，机器引用字段与逐字原话仍必须保留。后续使用新冻结构建重新运行，旧试验不会追改为成功。

### 预绑定评价对象（已实现，质量验收进行中）

## 必经审校与恢复

[决策记录](./adr/0003-required-analysis-refinement.md)：新 v2 请求固定 `report-review-rewrite-v1` 策略，初稿先通过同一目录的结构、原文、来源与覆盖校验，作为私有候选保存。独立审校输入为完整原模型材料及此未发布初稿，不包含供应商思维链；输出完整修订稿，再执行相同本地验证。模型审校不是事实证明，最终质量仍需单独审读。
