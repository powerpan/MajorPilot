## 1. 共同设计目标

三个任务不是考试、课程缩写版或职业测评。它们需要让没有 Python 经验的学生在 45–60 分钟内实际完成一次具有代表性的工作，并产生足以支持反思和比较的证据。

共同原则：

- 学生必须做出选择、修改或解释，不能只阅读内容；
- 每项任务都有一个清楚的最终成果；
- 基础路径不要求自行搭环境或从空白写代码；
- 专业核心体验高于表面上的数据和页面复用；
- 允许多种合理结论，不把唯一标准答案当作专业体验；
- 提示只在学生主动请求时出现，并采用三个层级；
- 评价聚焦过程证据，不生成综合适配分数；
- 所有数据和人物均为合成，不影射真实学校或学生；
- Task Version 一经 Experience Run 开始即固定。

## 2. 共同业务情境

首批任务使用虚构在线学习平台 **LumenLearn**：平台发现一个新课程群体的完成率下降，希望团队理解问题并改善学习支持。

共享背景事实：

- 平台提供短期线上职业课程；
- “完成”定义为在规定周期内完成核心单元和最终作业；
- 最近若干批次的完成率出现下降；
- 团队拥有学习行为、支持请求和聚合运营数据；
- 数据只能支持有限判断，不能直接证明所有因果关系；
- 团队希望采取小范围、可验证的改进，而不是一次性大改产品。

三个专业从同一问题进入，但承担不同角色：

| Major | 角色 | 核心问题 | 最终成果 |
| --- | --- | --- | --- |
| AI | AI 产品／模型分析助理 | 支持请求分类系统为什么出错，如何改进并安全使用 | 模型错误分析与改进建议 |
| Data Science | 初级数据科学分析师 | 哪些数据关系值得关注，结论有多确定 | 可复核的数据分析摘要 |
| Business Analytics | 业务分析师 | 完成率下降发生在哪个环节，应优先采取什么行动 | 指标诊断与行动实验方案 |

## 3. 共享数据资产

所有资产使用固定随机种子生成，并随 Task Version 保存校验值。

### 3.1 学习行为数据

`learner_activity.csv` 建议包含约 360 条合成记录：

- `learner_id`：无业务含义的合成标识；
- `cohort_week`：加入批次；
- `course_track`：课程方向；
- `signup_source`：自然、合作渠道、活动等；
- `device_group`：desktop、mobile、mixed；
- `lessons_started`、`lessons_completed`；
- `assignment_submit_rate`；
- `avg_session_minutes`；
- `days_to_first_lesson`；
- `forum_visits`；
- `support_contacts`；
- `completed`。

数据包含少量缺失、一个明确重复行和几个合理极端值，用于体验数据质量判断。数据不包含真实姓名、学校、国籍、性别、年龄、健康或其他敏感属性。

### 3.2 支持请求数据

`support_messages.csv` 建议包含 60–80 条简短合成消息及人工审核标签：

- `message_id`；
- `message_text`；
- `gold_label`；
- `baseline_prediction`；
- `baseline_confidence`；
- `split`：practice 或 evaluation。

此 CSV 是内容仓库的完整主数据，只供审核和服务端使用，不能作为 public 静态资产整体下发。发布流水线派生 `practice_public.json`（练习文本、标签、baseline）和 `evaluation_public.json`（评价文本与匿名 sample id，不含 gold_label），以及只供服务端的 `evaluation_private.json`。客户端 manifest 不能包含私有资产路径或下载地址。正式评分服务端执行；浏览器只预览练习集，不能靠隐藏 UI 保护答案。

首版标签固定为：

- `technical_issue`：登录、页面、音视频、提交等技术问题；
- `concept_confusion`：无法理解课程概念或题目；
- `schedule_constraint`：时间、截止日期和进度安排；
- `motivation_support`：挫败、犹豫或需要学习鼓励。

消息不得包含危机干预、医疗、心理诊断或真实个人信息，以免任务范围转向高风险内容。

### 3.3 业务漏斗数据

`weekly_funnel.csv` 建议包含 12 周、课程方向和来源渠道的聚合记录：

- `week`、`course_track`、`signup_source`；
- `enrolled_count`；
- `first_lesson_count`；
- `week_one_active_count`；
- `assignment_started_count`；
- `assignment_submitted_count`；
- `completed_count`；
- `support_contact_count`。

聚合数据与学习行为数据使用同一生成逻辑，但允许为任务清晰度保留不同粒度。

## 4. 共同任务结构

| 阶段 | 时间 | 学生行为 | 系统产出 |
| --- | ---: | --- | --- |
| 情境与成果 | 5分钟 | 理解角色、问题、数据和最终交付 | 开始前确认 |
| 最低必要知识 | 8–10分钟 | 完成小型交互示例 | 概念检查，不计总分 |
| 核心分析 | 25–30分钟 | 检查、修改、运行、选择并解释 | Step Response、运行结果 |
| 决策与边界 | 5分钟 | 给出结论、限制和下一步 | 核心任务成果 |
| 反思 | 8–10分钟 | 描述兴趣、困难和继续意愿 | Reflection |

预计总时长 51–60 分钟。页面显示的是参考时间，不以倒计时强迫完成。

## 5. AI 专业体验

### 5.1 体验目标

让学生体验 AI 工作中常见的“定义任务—检查输出—分析错误—调整有限配置—比较结果—判断使用边界”闭环，而不是只编写提示词或观看模型回答。

### 5.2 最终成果

一份结构化的模型改进建议，包含：

- 两类主要错误模式；
- 对标签规则、示例或阈值的有限调整；
- 调整前后评价结果比较；
- 是否建议小范围上线；
- 一个不能由当前结果消除的风险。

### 5.3 步骤

| 步骤 | 建议时间 | 学生操作 | 可形成的证据 |
| --- | ---: | --- | --- |
| A1 认识分类任务 | 5分钟 | 查看四类支持请求及路由用途 | 能区分任务目标与生成式聊天 |
| A2 理解评价 | 8分钟 | 使用小例子理解混淆矩阵、precision 和 recall | 对错误代价的选择与解释 |
| A3 检查错误 | 10分钟 | 检查 8–10 个 baseline 错误，归纳模式 | 错误分组及引用样本 |
| A4 设计修改 | 10分钟 | 从规则澄清、补充示例、阈值调整中选择并配置修改 | 修改理由和预期影响 |
| A5 固定集评估 | 10分钟 | 在页面提交配置，由服务端确定性评估隐藏集，比较前后指标和错误类别 | 正确读取变化及权衡 |
| A6 使用决定 | 5分钟 | 选择继续试验／有限上线／暂不上线并说明监控项 | 决策与风险边界 |
| A7 反思 | 8分钟 | 回答兴趣、困难、意外和继续意愿 | 学生自述 |

### 5.4 可修改范围

MVP 只允许修改预定义配置：

- 从经审核的标签定义变体中选择；可以补充自己的解释，但解释文本不自动变成模型指令；
- 从候选示例池选择有限示例；
- 一个置信度阈值；
- 低置信度时转人工的策略。

学生不能上传任意模型、调用外部网络、修改评价集标签或看到隐藏评价答案。

### 5.4A 确定性分类与评分合同

本任务使用公开说明的教学级轻量文本分类器，不调用在线大模型产生评价集预测，不声称学生重新训练了大模型。配置为 `definitionVariantIds`（每标签一个审核变体）、`exampleIds`（候选池最多4个、不重复）、`confidenceThreshold`（0.40／0.55／0.70）和 `lowConfidencePolicy`（MANUAL_REVIEW／AUTO_ROUTE）。任意定义文本只保存为修改理由，不影响计算。

固定 Task Version 同时发布以下资产及哈希：基础训练词计数、词表、标签顺序、定义变体的特征词清单、带审核标签的候选示例池、公开练习集、私有评价集。正式算法 `classifier-v1`：

1. 文本 NFKC 规范化、转小写，去 Unicode 空白和标点，按 Unicode code point 取相邻双字符；只保留冻结词表内特征，词表外忽略；
2. 从固定基础训练计数开始，所选候选示例按审核标签各追加一次特征频数；定义变体的每个特征词为该标签增加1次伪计数，不修改词表；
3. 四个标签先验均为1/4，使用加一平滑多项朴素贝叶斯：`logScore(c)=log(1/4)+sum(n(t)*log((count(c,t)+1)/(total(c)+|V|)))`；
4. 固定标签顺序 technical_issue → concept_confusion → schedule_constraint → motivation_support；logScore 先四舍五入至小数点后6位，再取最大值，同值按标签顺序；用稳定 softmax 得 confidence，比较阈值前同样保留6位；
5. MANUAL_REVIEW 且 confidence 小于阈值时拒绝自动路由，否则输出最高概率标签；等于阈值允许自动路由。baseline 使用默认变体、不追加示例、阈值0.55、MANUAL_REVIEW；
6. 浏览器仅在公开练习集运行同一算法作预览；正式评价服务只读取服务端存储的输入 revision，重新计算全部预测和指标并生成 SERVER_VERIFIED 执行记录，不接受客户端的“正确率”。

指标明确分母：coverage=自动路由数/N；自动路由准确率=正确自动路由数/自动路由数（无自动路由时为 null）；总集正确自动路由率=正确自动路由数/N；人工复核数单列。按标签给 precision 和 recall：precision 分母为自动预测到该标签数，recall 分母为该标签全部真实样本数（包括转人工）；零分母为 null，不填0。混淆矩阵增加 MANUAL_REVIEW 列。前后差值使用同一固定评价集，不能拿减少 coverage 冒充全面改善。

评价接口只返回聚合指标、混淆矩阵和错误类别计数，不返回隐藏集逐条 gold_label 或逐样本对错；用公开练习集样本解释具体错误。每 Run 最多5种不同配置的正式评估，相同配置哈希重试返回原结果、不重复扣次数；练习预览不占次数。此限制减少反复探测，但不承诺聚合统计能提供考试级答案保密。失败、断网和服务端超时不消耗成功次数。

内容发布黄金样例至少包括：相同配置重复结果一致、空命中特征按固定标签打平、同值决策、恰好阈值、全部转人工、零分母和新增示例后的计数变化。指标演算例：4条真实标签 T/C/S/M，路由 T/C/T/人工，应得 coverage=3/4、自动准确率=2/3、总集正确自动率=2/4；T precision=1/2、T recall=1，M precision=null、M recall=0。完整数据资产和跨语言算法测试在 P3 实现，不将本设计演算当浏览器验证。

系统提供的 baseline 不占学生5种配置额度。配置哈希使用固定 Task Version、按标签排序的变体 id、排序后的 exampleIds、枚举阈值及策略；相同集合的点击顺序不产生新配置。基础训练、示例池和评价 split 必须无 sample id 重叠；预计算 baseline 必须与同版本计算器一致。小数舍入使用明确的 half-up 规则（负值恰好中点远离0），前后端用相同测试向量，不能依赖语言默认 round 的差异。

### 5.5 评价规则

评价不是“最终准确率越高越好”，而是检查：

- 是否识别真实错误模式；
- 修改是否对应观察到的错误；
- 是否能正确比较改进和退步；
- 是否注意某类错误的实际影响；
- 是否给出与证据相符的上线决定；
- 是否说明评价集规模和代表性限制。

### 5.6 分层提示

- 一级：提醒检查错误集中在哪些标签或措辞；
- 二级：提示把错误按“定义不清、示例不足、低置信度”分类；
- 三级：指向一个具体样本和一个可尝试配置，但不替学生选择最终方案。

## 6. Data Science 专业体验

### 6.1 体验目标

让学生体验“检查数据—处理质量问题—探索关系—检验解释—表达不确定性”的过程，避免把预测准确率等同于数据科学全部工作。

### 6.2 最终成果

一份结构化分析摘要，包含：

- 两个数据质量处理决定；
- 两到三个有证据支持的发现；
- 一个不能从当前数据推出的因果结论；
- 一个值得进一步收集或验证的问题。

### 6.3 步骤

| 步骤 | 建议时间 | 学生操作 | 可形成的证据 |
| --- | ---: | --- | --- |
| D1 理解字段与问题 | 5分钟 | 查看数据字典和完成率问题 | 识别目标与观察单位 |
| D2 数据质量检查 | 8分钟 | 发现缺失、重复和极端值，选择处理方式 | 数据质量判断和理由 |
| D3 初步分布 | 6分钟 | 查看完成率和关键变量分布 | 正确读取样本和比例 |
| D4 探索关系 | 10分钟 | 选择两个变量，生成分组图或散点图 | 图表选择和观察 |
| D5 检查解释 | 8分钟 | 比较分组、置信区间或简单模型结果 | 不确定性与混杂判断 |
| D6 写出结论 | 6分钟 | 选择支持、不支持或证据不足，并说明限制 | 事实、解释和限制分离 |
| D7 反思 | 8分钟 | 回答兴趣、困难、意外和继续意愿 | 学生自述 |

### 6.4 操作方式

基础路径提供可运行代码单元和界面控件。学生可以：

- 选择缺失值处理方案；
- 删除明确重复记录；
- 选择变量、分组和图表；
- 修改一到两个安全参数；
- 运行预置统计或简单模型；
- 编辑结论文本。

代码区域显示真实、短小且可解释的 Python，但不要求从空白编写。可选进阶步骤允许修改有限表达式。

### 6.5 评价规则

- 是否发现明确的数据质量问题；
- 处理方式是否与字段含义一致；
- 图表或统计结果是否支持所写发现；
- 是否区分相关关系和因果解释；
- 是否注意样本量、缺失或选择偏差；
- 是否提出可验证的下一步。

学生选择不同但合理的数据处理方法时，可以得到不同数值结论；系统评价证据链，不要求完全相同的数字。

### 6.6 分层提示

- 一级：提醒检查行数、缺失比例和目标字段；
- 二级：提示比较处理前后的样本量或分布；
- 三级：指向一个具体字段和可运行操作，但不替学生写最终结论。

## 7. Business Analytics 专业体验

### 7.1 体验目标

让学生体验“澄清业务问题—定义指标—定位变化—选择优先级—提出可验证行动”的过程，和 Data Science 的个体级数据推理形成明确区别。

### 7.2 最终成果

一页结构化行动建议，包含：

- 主指标及定义；
- 最值得优先处理的漏斗环节和群体；
- 一个基于现有数据的业务假设；
- 一个小范围行动或实验；
- 成功指标、护栏指标和复盘时间。

### 7.3 步骤

| 步骤 | 建议时间 | 学生操作 | 可形成的证据 |
| --- | ---: | --- | --- |
| B1 澄清业务问题 | 5分钟 | 区分完成率下降、收入下降和满意度问题 | 问题边界 |
| B2 定义指标 | 7分钟 | 选择分母、时间窗口和主指标 | 指标定义一致性 |
| B3 定位漏斗 | 8分钟 | 比较报名、首次学习、第一周、作业和完成环节 | 正确定位主要下降 |
| B4 细分比较 | 8分钟 | 按课程或来源选择一个细分维度 | 优先群体及样本意识 |
| B5 形成假设 | 7分钟 | 区分观测现象、可能原因和未知信息 | 假设边界 |
| B6 设计行动 | 8分钟 | 选择行动、成功指标、护栏和复盘时间 | 行动可验证性 |
| B7 反思 | 8分钟 | 回答兴趣、困难、意外和继续意愿 | 学生自述 |

### 7.4 操作方式

学生使用预置表格和图表构建器：

- 修改指标定义；
- 选择时间范围和细分维度；
- 比较绝对数量与转化率；
- 排序候选问题；
- 从候选行动中选择或编辑一项；
- 为行动配置成功指标和护栏指标。

基础任务不要求 SQL。可选进阶区域可以显示生成该结果的短 SQL，供学生理解但不作为完成条件。

### 7.5 评价规则

- 指标分子、分母和时间窗口是否一致；
- 是否定位到数据支持的漏斗变化；
- 是否避免只看百分比而忽略样本量；
- 是否把现象和原因假设分开；
- 行动是否对应已识别问题；
- 是否定义可观测的成功和副作用指标。

### 7.6 分层提示

- 一级：提醒确认完成率的分母和时间窗口；
- 二级：提示先比较漏斗各环节再选择细分；
- 三级：指向变化最大的一个环节，但不替学生决定行动方案。

## 8. 三个专业必须保持的差异

| 维度 | AI | Data Science | Business Analytics |
| --- | --- | --- | --- |
| 主要分析对象 | 模型输出与错误 | 个体级数据和统计关系 | 聚合指标、漏斗和业务动作 |
| 核心迭代 | 修改模型配置并重新评价 | 修改数据处理或分析并重新检查 | 修改问题定义、优先级和行动方案 |
| 主要不确定性 | 模型泛化和错误代价 | 样本、测量、混杂和因果限制 | 业务原因、执行约束和指标副作用 |
| 最终表达 | 是否以及如何使用模型 | 数据支持什么、不支持什么 | 先做什么、如何验证 |
| 不应退化为 | 提示词聊天 | 只做图表或跑预测 | 只看仪表盘或写空泛建议 |

复用组件时不得消除这些差异。如果共享界面让三个任务都变成“看图后写几句话”，应优先调整任务，而不是追求前端复用率。

### 8.1 固定 Reflection 合同

三个专业使用同一字段结构，选项中的环节名称来自各自 Task Version：

| 字段 | 必填 | 规则与用途 |
| --- | --- | --- |
| `interesting_step_keys` | 是 | 选1–3个合法步骤，或 NONE；只表达自述兴趣 |
| `difficulty_sources` | 是 | 知识／工具／时间／任务方式／其他／没有明显困难，最多3项；最后一项互斥 |
| `continue_similar_work` | 是 | YES／UNSURE／NO，不作为能力结论 |
| `reflection_note` | 否 | 最多500字，解释意外、挫败或兴趣；不直接参与推荐排序 |
| `next_work_style` | 否 | MODEL_ITERATION／DATA_REASONING／BUSINESS_ACTION／UNSURE；跳过保存显式 SKIPPED；是 NEXT 唯一的明确工作方式输入 |
| `ai_follow_up` | 否 | 最多1次追问与回答；失败可跳过，不改变核心必填状态或 NEXT 排序 |

固定反思问题和 schema 由 question_set_version 锁定；AI 追问仅在学生主动请求时生成，不能新增必填项。提交反思会冻结全部必填回答及已填写可选项，暂停反思不提交、不算完成。

## 9. 通用失败与恢复状态

| 失败 | 学生端处理 | 后端／分析记录 |
| --- | --- | --- |
| 数据资产加载失败 | 保留步骤，提供重试，不允许提交空结果 | 资产版本、错误类型，不记录密钥 |
| 浏览器执行超时 | 停止 Worker，保留输入，可恢复到上次结果 | Task Version、步骤、时间和错误类 |
| 学生输入无法解析 | 指明具体字段，不清空其他输入 | 记录验证失败类型，不复制完整敏感文本 |
| AI 提示失败 | 显示静态分层提示或稍后重试 | 模型调用状态和降级路径 |
| 自动保存冲突 | 使用版本号提示刷新或合并，不静默覆盖 | 请求版本和当前版本 |
| 网络短暂中断 | 本地暂存允许的草稿，恢复后按顺序提交 | 重复请求保持幂等 |
| 报告生成失败 | 任务仍显示完成，报告显示生成失败和重试状态 | 独立报告失败状态 |

## 10. 内容审核与发布门槛

每个 Task Version 发布前必须完成：

1. 专业内容审核：任务是否代表该专业的真实工作方式；
2. 教学可达性审核：无相关经验者能否理解最低必要知识；
3. 数据审核：合成数据、字段、数值和标准结果一致；
4. 证据审核：每个报告字段都有允许来源；
5. 提示审核：三级提示不会提前泄露核心答案；
6. 公平性审核：背景自评不会成为完成门槛；
7. 浏览器审核：Chrome 和 Edge 的结果一致；
8. 时长审核：目标用户中位完成时间在 45–60 分钟；
9. 失败恢复审核：刷新、断网和执行错误不会清空进度；
10. 版本审核：内容、数据、评价、提示和报告映射使用同一 Task Version。

## 11. 任务级验收

- 三个任务均能在没有工作人员介入时从开始走到 Reflection；
- 每项任务至少产生三类可追溯 Experience Evidence；
- 学生不请求提示时不会被 AI 主动打断；
- 请求三级提示后仍需学生作出核心选择；
- 不写代码的学生可以完成基础路径；
- 修改或运行只能访问 Task Version 声明的资产；
- 合理但不同的路径不会仅因数值不同被判为错误；
- 任务结果不会生成专业适配度总分；
- 完成一个任务后能够清楚解释与另外两个专业体验的差异；
- 内容和数据更新不会改变已开始的 Experience Run。
