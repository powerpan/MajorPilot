## 1. 工程目标

工程设计的目标不是提前写完实现，而是让后续开发者能够在不重新解释产品边界的前提下完成以下工作：

- 可重复地导入、构建和运行固定版本的 RuoYi 基线；
- 将学生端、管理端和后端单体分开开发，但共享一套版本化契约；
- 用迁移、内容校验和自动化测试保护用户数据与任务版本；
- 在不依赖容器的本地 macOS 环境完成开发和验收；
- 未来迁移到服务器或容器时不重写产品核心逻辑；
- 让每项测试都能追溯到产品、数据、接口、安全或内容设计。

## 3. 仓库目录

正式脚手架采用一个主仓库，建议目录如下：

```text
MajorPilot/
├── backend/                 # RuoYi Spring Boot 单体和 ruoyi-majorpilot 模块
├── admin-web/               # 固定版本的 RuoYi Vue 3 TypeScript 管理端
├── student-web/             # 自建 Vue 3 TypeScript 学生端
├── content/                 # 问卷、规则、任务、数据集、提示词及 schema
├── database/
│   ├── baseline/            # 经核对的上游初始库脚本，只读基线
│   ├── migration/           # Flyway 增量迁移
│   └── seed/                # 可重复的非生产种子数据
├── contracts/               # OpenAPI、JSON Schema 和事件 schema
├── scripts/                 # 环境检查、启动、停止、校验、测试脚本
├── docs/                    # 产品和工程设计
├── .env.example             # 仅变量名与安全默认值
├── .gitignore
├── UPSTREAM.md              # 上游来源、commit、许可证、导入和补丁记录
└── README.md                # 唯一的本地启动入口
```

`content/` 是受版本控制的产品内容，不是后台随意编辑的数据库文本。管理端在 MVP 中只允许查看、发布已校验内容版本和切换生效版本，不提供任意在线脚本编辑器。

## 4. 后端模块边界

在上游多模块 Maven 结构中新增 `ruoyi-majorpilot`，依赖通用能力但不让通用模块反向依赖产品业务。

```text
ruoyi-majorpilot
├── identity        学生注册、验证、登录、会话和密码重置
├── intake          Intake Session、答案和 Decision Profile
├── recommendation  规则、理由、改选和下一专业推荐
├── content         任务版本、内容清单和发布校验
├── experience      运行、步骤、自动保存、执行、提示和反思
├── report          证据快照、声明、单专业和比较报告
├── analytics       事件写入、聚合查询和受控导出
├── privacy         同意、导出、删除和留存任务
├── integration     AI、邮件、浏览器结果等适配接口
└── support         内部支持和敏感操作审计
```

学生 Controller 只暴露 `/api/public/v1/**` 和 `/api/app/v1/**`；管理 Controller 只暴露 `/api/admin/v1/majorpilot/**`。两类安全过滤链、身份主体和权限注解必须分开，不能在 Controller 内用条件分支模拟隔离。

## 5. 前端工程边界

### 5.1 学生端

学生端采用 Vue 3、TypeScript、Vite、Vue Router、Pinia。组件库在脚手架验证中选用与产品视觉兼容、维护活跃的一套，但必须满足：

- 支持表单校验、对话框、通知、进度、标签页和无障碍基础属性；
- 不把 RuoYi 后台导航或权限菜单复制到学生端；
- 服务端数据通过独立 API client 和 query/cache 层管理，Pinia 不作为数据库镜像；
- 所有任务回答先写本地草稿，再通过带 revision 的自动保存提交；
- 页面刷新后以服务端状态为准，未同步草稿需要明确恢复提示；
- 执行引擎运行在 Web Worker 中，不阻塞主线程。

### 5.1A 本地草稿隐私与恢复

仅任务／反思／反馈允许的未同步输入进入 IndexedDB，key 包含 `studentPublicId + runId/contextId + stepKey + taskVersion`，记录 serverRevision 和 expiresAt；不保存密码、凭证、报告正文或模型上下文。默认7天过期，成功同步后立即清理对应草稿。进入页面先确认当前身份再读取同账户草稿，不先渲染缓存再检查登录。

主动退出、密码／邮箱变更导致退出、切换账号和删除确认时清理原账户草稿与内存事件缓存；清理只针对 MajorPilot 的存储命名空间，不清空浏览器其他站点数据。有未同步输入时明确提示“退出将清除这台设备上的未同步草稿”，允许取消退出先保存，不能声称未上传内容已保存到服务器。自然会话过期只锁住草稿，原账户重新登录可恢复；登录成其他账户则清掉前一账户草稿。

旧设备收到401／账户失效时执行相同清理；离线设备不能被服务器远程保证即时擦除，依靠身份门禁、7天 TTL 和再次联网校验处理，隐私说明写明此限制。使用 BroadcastChannel 通知同站点其他标签页清理；刷新或恢复前检查服务端 revision，不自动覆盖 PAUSED／CLOSED 状态。

组件库的最终选择不改变页面信息架构和 API 契约，因此属于 P0 脚手架验证，不阻塞设计完成。

### 5.1B 背景资料草稿

背景资料与上述任务草稿使用不同存储。服务器在账户的 `profile_draft_json`、`profile_draft_revision` 保存一份独立草稿；正式提交追加 Decision Profile，取消仅清草稿。revision 在提交或取消后仍递增，与 `baseProfileVersion` 一起阻止旧标签页覆盖新资料。

浏览器使用按 Student ID 隔离的 sessionStorage 保存当前填写、步骤和待确认提交的幂等键；没有单独的7天 TTL，不套用任务 IndexedDB 的留存承诺。读取前确认身份，退出／身份变化时清理；正式提交或取消成功后清理本机对应缓存。保存失败保留未同步内容，重新读取服务器版本前由用户明确放弃本机更改。服务端草稿没有独立到期时间，纳入个人导出与账户删除。

没有正式资料但已有草稿时，直接开始体验不能提交草稿或改变其 base 版本。体验绑定明确空快照；用户后续提交正式版本不修改既有 Run、报告或推荐的原始引用。

### 5.2 管理端

管理端基于固定的 RuoYi Vue 3 TypeScript commit。导入时保留其 Vue、Element Plus、Pinia 和 Vite 基线，先完成构建与登录验证，再做最小裁剪。不得为了和学生端统一视觉而重写管理端基础布局。

上游当前 `package.json` 为 RuoYi 3.9.2，并使用 Vue 3.5、TypeScript、Vite 6、Element Plus 和 Pinia；上游 README 建议 Yarn，但仓库未提交 lockfile。MajorPilot 会转换为统一的 npm lockfile，依赖本身先不做无关升级。

## 6. 上游导入与同步

首次导入必须形成可审计记录：

1. 记录仓库 URL、分支、commit、导入日期和 MIT 许可证；
2. 保存原始 commit 的校验值，不直接跟踪移动分支；
3. 原样完成一次后端编译、管理端构建和基础登录；
4. 将裁剪与安全加固拆成单独提交；
5. `UPSTREAM.md` 记录每处通用层修改及原因；
6. 以后只选择性吸收安全修复和已确认 bug fix；
7. 上游更新先在临时分支合并并执行完整回归，不直接覆盖主线。

P0 验证失败时保留原始错误、环境版本和最小复现，再决定修补或重新选型。不得静默更换 RuoYi 分支。

## 7. 配置与密钥

配置分三层：

- 仓库内安全默认值：端口、非敏感功能开关、日志级别示例；
- 本地环境文件：数据库密码、邮件测试器配置、Bailian API Key 和模型端点；
- 数据库运行配置：经权限控制的产品参数，不含任何供应商密钥。

建议本地文件名为 `.env.local`，由启动脚本读取并导出给 Spring Boot；仓库只提交 `.env.example`。必须执行：

- `.env.local`、IDE 私有配置、日志和本地数据库目录写入 `.gitignore`；
- 启动前检查必需变量，只打印缺失变量名；
- 前端只允许 `VITE_` 开头的公开配置，密钥变量不得使用此前缀；
- Spring Boot 配置中用 `${VARIABLE_NAME}` 引用，不设置真实密钥默认值；
- HTTP 授权头、Cookie、密码、重置令牌和模型请求体进入日志前脱敏；
- CI 运行 secret 扫描，并检查构建产物中是否出现测试密钥标记；
- 本地环境文件权限建议为 `0600`。

## 8. 数据库迁移与事务

数据库采用单向、不可改写的迁移序列：

```text
V1__ruoyi_baseline.sql
V2__majorpilot_identity.sql
V3__majorpilot_intake_and_recommendation.sql
V4__majorpilot_content_and_experience.sql
V5__majorpilot_evidence_and_reports.sql
V6__majorpilot_analytics_privacy_audit.sql
```

实际拆分可以更细，但已经在任何共享环境执行过的迁移不得修改；修复使用新迁移。上游初始 SQL 在导入时正规化为受控基线，Flyway 从空库和已有基线库两条路径都要验证。

关键事务边界：

- 注册认领 Intake：账户、Intake 归属和同意记录一次提交；
- 首次开始体验：运行、任务版本绑定和唯一活动约束一次提交；
- 步骤提交：revision 比较、响应修订和进度状态一次提交；
- 完成体验：反思、完成状态、证据快照创建请求一次提交；
- 发布报告：验证通过的报告版本、声明和证据链接一次提交；
- 删除账户：先撤销会话，再异步执行可识别数据处理并留最小审计证明。

所有时间在数据库使用 UTC，API 用 ISO 8601，界面按用户时区显示。ID 对外使用不可枚举标识；数据库内部主键是否用 bigint 不影响对外契约。

## 9. 版本化内容流水线

每个内容版本包含：

- `manifest.json`：内容类型、语义版本、状态、校验和和兼容 schema 版本；
- 问卷字段与选项；
- 推荐规则和理由模板；
- 三个专业任务定义；
- 合成数据集及数据字典；
- 提示层级和安全限制；
- 报告提示词、JSON Schema 和确定性回退模板。

流水线依次执行：schema 校验、引用完整性、唯一 ID、时间预算、证据白名单、数据集校验和、禁止外链/真实个人信息扫描、固定样例黄金测试。只有全部通过的不可变版本可发布。进行中的 Experience Run 永远绑定开始时的版本；撤回版本只阻止新运行，不改写旧记录。

## 10. 浏览器执行架构

MVP 采用“执行适配器 + Web Worker + 任务白名单”边界。优先候选是 Pyodide 类 Python/WASM 运行时，但确切版本必须在 P0 小实验中根据体积、冷启动、内存和 Chrome/Edge 一致性固定。

Web Worker 只解决线程与主界面分离，本身可访问 fetch、WebSocket 等能力，不是安全沙箱（见 [MDN 官方说明](https://developer.mozilla.org/en-US/docs/Web/API/Web_Workers_API/Using_web_workers)）。首版只执行版本化可信模板与校验参数；用户文本不得拼接到 Python/JS 源码。有限表达式必须经独立小语法解析器转成白名单计算树，禁止 import、属性访问、反射、动态 eval 和 JS bridge；不接受完整 Python 程序。

执行资源使用不同 hostname、无账户 Cookie、无业务 API 的隔离来源；只换端口不算 Cookie 隔离，凭证 host-only 且不共享父域。执行 origin、消息来源／类型／nonce 和资产哈希需验证，主页面不向执行端传入 Session、CSRF、私有报告或隐藏答案。仅固定启动器加载审核运行时资产；计算期 CSP 的 connect-src 为 none，脚本／Worker 源受限，资源由可信启动器预加载并传递。P0 必须证明此启动／计算隔离在 Chrome/Edge 可行；不能只靠覆盖 window.fetch 或字符串黑名单假装禁网。

用户设备文件选择器、文件句柄、持久化浏览器存储和主站 API 不授予执行器。允许的内存虚拟文件系统仅含当前任务合成数据，Worker 销毁即丢弃。每次任务默认10秒执行上限、100KiB输出／结果上限、1MiB输入上限；限制数组规模和操作次数，不声称浏览器提供可移植的硬内存配额。

浏览器执行必须满足：

- Worker 与主页面通过类型化消息协议通信；
- 仅挂载当前任务的只读合成数据和允许的初始代码；
- 禁止任意网络请求和本地文件访问；
- 设置执行超时、输出长度和结构化结果上限；
- 每次运行生成 client execution id，服务端幂等接收摘要；
- 服务端不信任浏览器声明的“正确”，只对允许字段重新验证；
- 保存代码差异、选定结果和错误类别，不默认保存无限制 stdout；
- Worker 崩溃可重建，不影响已提交步骤和答案。

P0 必须完成真实引擎 spike；隔离或性能不达标时，关闭可编辑表达式，只保留界面参数、可信固定计算器和等价只读 Python 展示，不运行用户代码。正式结果走服务端白名单计算器或完整覆盖允许配置的预计算表；两者都必须保持相同输入输出和版本语义，不能对不同输入返回同一演示结果。未经单独设计不引入任意代码服务端执行。

AI 分类的练习预览与隐藏集正式评分按 `09` §5.4A 分开。任务发布检查 public manifest、资源包与网络返回均无 hidden gold_label；服务端重算评分，不因客户端声称执行成功就信任其数值。P3 内容资产未发布前，该教学分类器算法只是合同，不是已验证的真实内容。

## 11. 外部服务适配器

### 11.1 AI

内部 `AiGateway` 接口接收版本化、最小化请求，返回结构化结果或明确错误类别。Bailian 是首个生产适配器，另提供：

- `FakeAiGateway`：单元和端到端测试的固定结果；
- `ReplayAiGateway`：使用脱敏录制响应进行回归；
- 可选 DeepSeek 离线评测适配器，不参与线上自动路由。

超时和 429 采用有限次数、带抖动的重试；业务请求有全局 deadline。报告生成失败一次结构化修复后进入确定性模板，不无限重试。

### 11.2 邮件

`MailGateway` 负责验证、重置和必要通知。本地使用邮件捕获器；测试使用内存假实现；未来真实 SMTP 只替换适配器。任何环境都不允许把验证链接直接写进普通应用日志。

### 11.3 单体持久化后台作业

采用 `11` §12A 的 MySQL job 表 + Spring 定时 worker，不引入消息中间件。领域变更和 job 插入同事务；每5秒扫描一次可用任务，以事务条件更新领取，租约60秒、每20秒心跳，lease_version 作为迟到写入栅栏。并发领取、心跳和最终发布都必须检查版本，定时器不承担唯一事实保存。

作业单次对外调用 deadline 不超过45秒；普通暂时错误最多3次尝试，AI JSON 修复最多1次且记录在报告版本阶段中。重启读取数据库恢复；旧作业未取得租约不能重放副作用。业务键保证一次关闭只排同一逻辑构建、一次报告版本只发布一次。模型调用可能因崩溃重复计费，记录 invocation id 与阶段，不能承诺外部供应商 exactly-once。

发布前锁定账户并检查不是删除／锁定状态；删除后迟到结果丢弃，按 `11` 清理引用。删除作业逐阶段持久化，失败告警并持续重试；30天目标不是静默等待窗口。首次失败和超过24小时未推进都告警，临近期限再次升级。报告／快照失败展示可理解状态，不能卡在 GENERATING 而无租约或可领取任务。

## 12. 本地启动与运行

脚手架完成后提供以下统一入口，具体脚本名可以调整但职责不可合并：

- `scripts/check-env`：只读检查 Java、Maven wrapper、Node、npm、MySQL、Redis、端口和必需变量；
- `scripts/bootstrap-local`：创建本地库、执行迁移和装载非生产种子；
- `scripts/start-local`：按基础设施、后端、学生端、管理端、邮件捕获器顺序启动；
- `scripts/stop-local`：仅停止由该项目记录的进程；
- `scripts/test-unit`、`test-integration`、`test-e2e`：分层验证；
- `scripts/verify-secrets`：扫描源码、日志与前端产物中的秘密标记。

启动脚本必须保存 PID 或使用进程管理文件，不能用模糊进程名批量终止。启动失败输出组件名、端口和日志位置，不输出环境变量值。

默认端口由脚手架确定并写入单一配置表。开发代理只代理明确 API 前缀，学生端和管理端 Cookie 不共享名称；生产部署时优先采用同站点反向代理以减少跨域复杂度。

## 13. 可观测性

后端日志采用结构化格式并携带：

- `request_id` 和必要时的 `trace_id`；
- actor type，而不是默认记录邮箱；
- endpoint template、状态码、耗时和错误代码；
- task version、run id、report id 的不可枚举标识；
- AI provider、model/prompt version、延迟、token/成本摘要和错误类别。

严禁记录密码、完整 Cookie/JWT、验证/重置令牌、API Key、任意完整问卷或自由文本、模型原始请求体。用户可见错误使用 `12` 中稳定错误代码；堆栈只进入本地受控日志。

最低运行健康检查：应用存活、数据库可用、Redis 可用、迁移状态。AI 和邮件故障显示为依赖状态，不应使基础健康端点伪装成全面可用。

## 15. 必须覆盖的测试场景

### 15.1 身份和权限

- 未注册访客完成 Intake 后注册，原 Intake 被一次性认领；
- 重复注册、过期验证、密码重置令牌重放均安全失败；
- 学生 A 无法读取学生 B 的运行、回答和报告；
- 学生 Cookie 不能调用管理 API，管理令牌不能直接充当学生；
- CSRF、退出和密码修改后会话撤销符合契约；
- 真实浏览器验证注册/退出 Cookie Path、两类 CSRF 的获取与轮换；删除确认后专用回执可查但正常资源全拒绝；
- 内部人员敏感查看和导出留下审计记录。

### 15.2 状态、并发和恢复

- 重复开始同一体验只得到同一个活动运行；
- 相同 Idempotency-Key 重试不重复创建副作用；
- 两个标签页提交旧 revision 返回冲突，不覆盖较新答案；
- 浏览器离线、刷新、Worker 崩溃、Redis 清空和后端重启后可恢复；
- 任务版本发布或撤回不改变进行中运行；
- 管理员只能创建有审计的恢复运行，不能改写学生答案。
- 并发切换、暂停后迟到保存、暂停反思再恢复、Ready 改选均符合 `06`；同时只有一个活动 Run，Closed 不被恢复；
- 在领域事务提交后、job 领取后、结果发布前分别杀进程，重启仍恢复；租约过期旧 worker 无权写回；
- 快照 FAILED 后追加版本可以 READY，唯一约束不冲突；删除确认与异步结果竞态不会复活数据。

### 15.3 推荐、任务和报告

- 所有规则边界、平局、缺失可选信息和用户改选都有固定样例；
- 将 `08` 的 I01–I09、N01–N09 和负向样例转为自动测试，且三种严格首选都不能被辅助信息越过；
- 将 `09` 分类器计数、舍入、打平、阈值和零分母样例用于前后端一致性测试；浏览器不含评价集答案；
- AI、DS、BA 三项任务的黄金数据产生预期证据；
- 非白名单事件和分析属性不能进入报告证据；
- AI 返回错误 JSON、无证据声明或供应商超时会进入修复或确定性回退；
- 旧报告继续引用原始 profile、task 和 evidence snapshot；
- 完成首项后下一专业推荐排除已完成项并说明差异；
- 两项完成后生成比较报告，来源可追溯。

本轮追加：背景单题／整份跳过后保留已有回答，缺失、主动跳过、不确定不同；排序不足不生成推荐但仍可自主开始。资料编辑覆盖独立草稿、取消、空白重填、刷新、失败与幂等重试、双标签冲突；新 Run 使用最新正式背景，旧 Run 与报告保持原绑定，包括旧 NEXT 作为选择依据的情况。支付演示完整点击、退出和刷新均不发送业务写请求，不改变账户、额度或任务状态。

### 15.4 隐私和留存

- Intake 认领、7 天匿名清理、180 天事件留存和 30 天删除处理符合设计；
- 删除请求立即撤销会话，之后无法登录；
- 导出不包含内部风险标记、密钥、令牌或其他用户数据；
- 日志和前端产物扫描不出现已植入的测试秘密标记。
- 退出／换账号／删除／TTL 到期清理本地草稿；自然过期仅原账户可恢复；不同账户绝不展示前一账户草稿；
- 事件接口的主体伪造、非法属性、重复批次、超限和客户端时钟异常均验证；事件失败不阻塞领域流程。

## 16. 合并和发布门禁

任何进入主线的变更至少满足：

1. 相关设计或合同已存在，需求编号可追溯；
2. 格式、静态检查和受影响单元测试通过；
3. 数据库变更使用新迁移，并证明空库升级和已有库升级路径；
4. API 变更同步 OpenAPI、错误码和前端类型；
5. 内容变更通过 schema、引用和黄金样例校验；
6. 安全敏感变更包含负向测试；
7. 前端关键状态有组件或端到端验证；
8. 未提交密钥、构建产物、运行日志和本地数据；
9. 变更说明列出验证结果和仍未执行的真实环境检查。

里程碑发布还需要完成 Playwright 主路径、安全回归、数据库备份/恢复演练、Chrome/Edge 人工验收和可重复新环境启动。公开部署不属于当前 MVP 设计阶段的完成条件。
